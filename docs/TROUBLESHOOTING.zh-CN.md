# SSRVPN 常见问题排查

先确认安装包来自正式 Release 或官网固定下载地址，并记录平台、SSRVPN 版本、复现步骤
和实际现象。新版本会为常见失败显示稳定错误编号；提交问题时可以提供编号，但不要公开
原始订阅、节点、Token、API secret 或未经检查的完整日志。

## 先使用“诊断与运行日志”

从“订阅”页右上角点击带文字的“运行日志”按钮，打开“诊断与运行日志”并等待当前检查完成。
诊断中心会先用一句话说明当前结论，再按中文检查项和本地时间列出最近运行记录，并给出错误
编号、影响和下一步动作。内部事件名、会话编号、路径及重复核心信息不会混在默认结果中；只有
深入排障时才需要展开默认收起的“技术明细（已脱敏）”。

- “重新检查”只重新读取当前状态，不会启动 VPN 或修改网络。
- 桌面端“修复”只在未连接、且能证明待恢复代理属于 SSRVPN 时可用；连接中不会为了修复
  而断开，不能确认所有权时也不会重置系统代理。
- “复制报告”生成的是有大小上限的脱敏文本。复制后仍应人工检查再发送，不要附带原始
  `config.yaml`、订阅地址、节点密码、Token 或崩溃转储。

错误编号用于稳定定位类别，不代表必须由用户手工修改系统。优先执行界面给出的安全动作；
若动作无效，再按下面的现象继续排查。

主页发生连接错误时会完整显示“原因、影响、下一步操作”。点击“查看诊断与解决建议”
可直接进入诊断。常见提示的含义如下：

| 提示 | 含义 | 优先操作 |
| --- | --- | --- |
| 尚未允许 VPN 连接 | Android 的系统 VPN 授权尚未通过 | 再次连接，在系统请求中选择允许或确定 |
| 已取消 TUN 授权 | macOS 管理员验证没有完成 | 需要 TUN 时重新连接，在系统窗口完成验证 |
| 本地控制服务认证失败 | 应用与本机 VPN 服务的连接信息不一致 | 完全退出并重新打开 SSRVPN；这不等于订阅账号密码错误 |
| 核心启动超时 | 设备上的 VPN 服务未在限定时间内就绪 | 重新连接，反复失败时重启应用并检查核心状态 |
| 服务器地址解析失败 | 当前网络没有成功解析服务器域名 | 确认普通网页可打开，再刷新订阅或切换节点 |
| 目标服务拒绝连接 | 目标地址的服务端口拒绝请求 | 刷新订阅或换节点；持续失败时联系提供方 |
| 安全连接校验失败 | 加密握手或证书验证没有完成 | 确认设备日期时间，更新订阅或切换网络 |
| 系统代理尚未确认生效 | macOS 尚未确认当前网络使用已提交的代理 | 网络稳定后重新连接；反复发生时检查其他代理软件 |
| 操作未完成 | 当前证据不足以确定具体原因 | 运行诊断，复制脱敏报告反馈 |

“运行异常记录”可能来自连接、界面或意外退出，不表示每次都发生了程序崩溃。应用能够
处理的连接失败保留在运行日志中；尚未捕获的异常仍会生成本机报告。

## 导入后没有节点

**现象**

导入订阅或节点后，主页仍为空，或者刷新立即失败。

**原因或检查**

- 链接复制不完整、已经失效，或服务商暂时不可达。
- 当前网络、DNS、其他 VPN 或代理阻止了订阅下载。
- 服务商只接受特定客户端标识，或者当前账号、Token、设备/IP 被拒绝或限流。
- 导入内容不是应用支持的订阅或节点格式。

**动作**

1. 确认使用完整的 HTTPS 链接，且前后没有多余空格。
2. 暂停其他 VPN 或代理，再到“订阅”页面刷新一次。
3. SSRVPN 会在明确的客户端兼容失败时自动尝试 Clash Verge、v2rayN 和 Shadowrocket 标识，无需反复删除或修改订阅。
4. 如果提示认证失败、地址失效或请求过于频繁，请向订阅服务商确认账号和链接，或等待限流恢复；不要把完整链接贴到公开 Issue。

## 点击连接后一直等待或很快断开

**现象**

状态长时间停在连接中，或刚显示连接便恢复未连接。

**原因或检查**

- 当前节点已经超时或订阅信息陈旧。
- TUN 所需的系统权限没有获得，或系统中已有其他 TUN/VPN 占用网络。
- 设备上的 VPN 服务或系统网络接管未能就绪。

**动作**

1. 刷新订阅并重新测试节点，选择一个未超时的节点。
2. 退出其他 VPN、代理和网络过滤工具后重试。
3. 桌面端先用系统代理验证节点；需要 TUN 时再按平台指南授予权限。
4. 仍失败时完全退出 SSRVPN 后重新打开，并保存已脱敏日志用于排查。

## 显示已连接但网页或应用无法联网

**现象**

SSRVPN 显示已连接，但网页打不开，或只有部分应用不走代理。

**原因或检查**

- 节点可连接但出口不可用，或目标网站拒绝该出口。
- 系统代理只覆盖遵循系统代理设置的应用。
- 其他代理软件在连接后又修改了系统代理或路由。

**动作**

1. 切换另一个节点并等待连接验证完成。
2. 浏览器可用而游戏或桌面客户端不可用时，按平台说明改用 TUN。
3. 关闭其他代理软件；断开 SSRVPN 后确认普通网络已经恢复，再重新连接。

## 断开后系统代理看起来不正确

**现象**

断开或退出后，浏览器仍显示代理错误，或者系统代理值与预期不同。

**原因或检查**

SSRVPN 只恢复能够证明由自己设置、且之后没有被其他软件改写的代理状态。多个代理软件
同时运行时，最后一次修改可能来自其他程序。

**动作**

1. 退出所有代理和 VPN 软件。
2. 在系统网络设置中检查代理开关，再测试直连网络。
3. 如仍异常，重新启动系统后先测试普通网络，再单独启动 SSRVPN。

## IPv6 节点或 IPv6-only 网站不可用

**现象**

IPv6 节点连接失败、IPv6-only 网站无法打开，或首页只显示 IPv4。

**原因或检查**

这是产品设计。SSRVPN 永久关闭 Mihomo 的 DNS AAAA 和 IPv6 连接；Android 与 Windows TUN 还会捕获并拒绝 IPv6，避免底层 IPv6 不完整时反复尝试不可达地址，也防止 IPv6 绕过 VPN。

**动作**

无需修改系统 IPv6 设置。请改用提供 IPv4 地址的节点和目标服务。

## macOS 无法直接打开应用

**现象**

首次打开时 macOS 阻止运行，或提示无法验证开发者。

**原因或检查**

当前公开 DMG 未使用 Developer ID 公证，Gatekeeper 会显示安全提示。

**动作**

只在确认安装包来自正式下载地址并核对 SHA256 后，到“应用程序”中右键 SSRVPN，选择
“打开”。不要用关闭系统安全功能的方式绕过提示。

## macOS TUN 授权取消或启动失败

**现象**

选择 TUN 后出现系统管理员授权窗口；取消、等待过久或授权后仍未连接。

**原因或检查**

- 用户取消了系统授权，或授权流程超时。
- 其他 VPN/TUN 正在占用路由。
- 核心或临时运行文件未通过启动检查。

**动作**

退出其他 VPN，重新连接并在系统窗口中完成授权。密码由 macOS 处理，不应输入到
SSRVPN 自己的页面。仍失败时断开并退出应用，确认网络恢复后再收集脱敏日志。

## Windows 安装包出现 SmartScreen 提示

**现象**

Windows 提示未知发布者，浏览器也可能提示保留或删除下载文件。

**原因或检查**

当前 Windows 安装器没有 Authenticode 签名。

**动作**

仅在文件来自正式下载地址且 SHA256 匹配时选择保留并继续运行。来源或哈希不确定时不要
绕过系统提示。

## Windows 提示找不到应用文件

**现象**

启动器无法找到 SSRVPN 应用文件。

**原因或检查**

安装目录不完整，内部 Flutter 程序或运行库被删除、隔离或损坏。

**动作**

从正式来源重新下载并校验 `SSRVPN_Setup.exe`，再运行安装器修复安装。不要从其他电脑
单独复制顶层 `ssrvpn_windows.exe`。

## Windows 启动时提示系统代理恢复未完成

**现象**

应用拒绝开始新的系统代理连接，诊断报告提示保留了代理恢复状态，或者异常退出后浏览器仍指向 `127.0.0.1` 的旧端口。

**原因或检查**

SSRVPN 在修改系统代理前保存原值，并由独立恢复入口处理崩溃或强制退出。恢复记录损坏、注册表暂时不可访问，或另一个代理软件已改写当前值时，应用会失败关闭并保留证据；它不会猜测原值，也不会覆盖其他软件的新设置。

**动作**

1. 完全退出 SSRVPN 和其他代理/VPN 软件，然后重新启动 SSRVPN，让恢复入口重试一次。
2. 打开“诊断与运行日志”执行重新检查；仅在未连接且界面能证明代理属于 SSRVPN 时使用安全修复。
3. 若仍失败，先在 Windows“网络和 Internet → 代理”中记录当前值并恢复正常直连，再提交脱敏诊断。不要直接删除应用数据中的 `system_proxy_backup.json`、事务锁或注册表恢复项，否则会丢失恢复依据。

## Windows 提示当前账户无法解密本机密钥

**现象**

启动页提示“当前 Windows 账户无法解密本机密钥”，并显示一个可复制的
`.api-secret.dpapi` 完整路径。应用不会自动删除或覆盖该文件。

**原因或检查**

该文件使用创建它的 Windows 登录用户通过 DPAPI 加密。把旧数据目录连同密钥文件复制到
另一台电脑或另一个 Windows 账户，或者密文文件损坏时，当前账户无法解密。订阅和设置
文件不依赖这次解密，仍应保留。

**动作**

1. 完全退出 SSRVPN，不要删除、上传或分享该密钥文件。
2. 按界面显示的完整路径找到 `.api-secret.dpapi`。常见位置是安装版的
   `%LOCALAPPDATA%\Programs\SSRVPN\bin\ssrvpn`、回退目录的
   `%LOCALAPPDATA%\SSRVPN\ssrvpn`。
3. 在原目录把文件重命名为
   `.api-secret.dpapi.unreadable-YYYYMMDD-HHMMSS`，保留它作为恢复证据。
4. 重新启动 SSRVPN。应用会为当前 Windows 账户生成新密钥；已有设置和订阅继续保留。

只有原 Windows 账户和原设备上下文可能解开旧密文。若要跨电脑或跨账户迁移数据，
复制前应退出 SSRVPN，并从副本中排除 `.api-secret.dpapi`，让目标账户首次启动时生成新值。

## Windows 安装版升级后订阅和设置被清空

**现象**

运行 `SSRVPN_Setup.exe` 安装或升级后，原有订阅、设置、缓存和窗口状态不再存在。

**原因或检查**

3.3.3–3.4.1 的安装器会清空固定安装目录、LocalAppData 回退配置和窗口状态；如果数据已
被这些旧版本删除，后续升级无法自动还原。自 3.4.2 起，覆盖升级、卸载以及保留数据后的
重装都会保留安装目录和 LocalAppData 中的订阅、设置、DPAPI 密钥与窗口状态，只清理程序
文件、旧恢复状态和两个已知 WebView 缓存目录。桌面或下载目录中的便携副本始终不会被搜索
或修改。因此，3.4.2 或更高版本执行上述流程后丢失数据不再是预期行为，应按缺陷排查。

**动作**

1. 先确认安装包和已安装版本；如果是 3.4.2 或更高版本，停止反复安装并备份仍存在的
   `bin\ssrvpn`、LocalAppData 回退目录和窗口状态文件，再保存安装日志用于排查。
2. 如果数据已被 3.3.3–3.4.1 删除，只能从用户自己的备份、便携副本或服务商处恢复并重新
   导入；不要公开上传订阅、节点、`.api-secret.dpapi` 或其他凭据文件。
3. 提交 3.4.2 或更高版本的数据丢失问题时，说明安装、升级、卸载或重装的具体路径和版本；
   可提供脱敏日志与文件是否存在、哈希是否变化的结果，不要提交凭据文件本身。

## Windows 关闭窗口后找不到应用

**现象**

关闭主窗口后应用仍在运行，但任务栏没有窗口。

**原因或检查**

启用最小化到托盘时，关闭窗口会隐藏到系统托盘。

**动作**

从系统托盘打开 SSRVPN 菜单并选择显示窗口。若窗口仍无法出现，可完全退出后使用发布包
中的 `ssrvpn_safe_mode.bat` 启动；`SSRVPN_Diag.bat` 可检查安装目录必需文件。

## Android 首次连接没有建立 VPN

**现象**

点击连接后系统没有建立 VPN，或应用很快回到未连接。

**原因或检查**

- 系统 VPN 授权未确认。
- 设备中已有另一个 VPN 正在运行。
- 系统后台限制终止了前台 VPN 服务。

**动作**

关闭其他 VPN，重新连接并确认 Android 的系统 VPN 授权。连接期间不要强制停止应用；如
系统限制后台运行，请在系统应用设置中允许 SSRVPN 正常运行。

## 更新下载或安装失败

**现象**

应用发现新版本，但下载、校验或覆盖安装失败。

**原因或检查**

- 当前网络无法访问 GitHub Releases 或其安装包下载地址。
- 下载文件不完整，SHA256 校验失败。
- Android 已安装包与正式 Release 使用的签名身份不同。

**动作**

1. 切换到稳定网络后重试，不要安装校验失败的文件。
2. 从正式 Release 手动下载对应平台产物并核对 SHA256。
3. Android 覆盖安装仍失败时，先确认现有应用是否来自正式渠道；卸载会清除本地数据，
   不要在未记录订阅和设置前直接卸载。

## 提交问题前

请提供平台、SSRVPN 版本、复现步骤、预期结果和实际结果。日志必须先
移除订阅 URL、Token、节点地址、密码和 API secret。Windows 崩溃转储可能包含敏感数据，
不要上传到公开 Issue；需要进一步分析时应通过维护者指定的私密渠道传递。
