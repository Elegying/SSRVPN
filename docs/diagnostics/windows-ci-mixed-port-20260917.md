# Windows CI 混合端口选择修复（2026-09-17）

v5.0.9 的 PR #250 和最终 main CI 均通过，正式 Release run 35225734861 的 Windows 代理流量验证却在核心启动阶段失败。核心日志明确显示 `listen udp 127.0.0.1:61472: bind` 被系统拒绝；没有进入流量统计断言或正式安装器构建。

责任层是测试夹具：`scripts/check-core-proxy-traffic.py` 的 `free_port()` 只绑定 TCP 0 端口后释放，不能证明同号 UDP 可用。Windows 可能单独保留该 UDP 端口。混合代理必须绑定两种协议。

修复使测试同时持有 TCP 和 UDP 探测 socket，只有两者都可绑定才返回端口。权限/占用冲突最多重选 32 次；其他系统错误直接保留，不增加核心启动等待，也不移除原断言。端口交给子进程前必须释放，仍存在通常的跨进程抢占窗口，本次不引入额外进程重试或端口管理抽象。

回归测试模拟此次 Windows UDP 10013 错误，确认跳过受限端口并释放全部 socket；验证访问拒绝/占用的有限退出和文件描述符耗尽错误不被吞掉。既有双栈测试复用同一端口 helper，因此无需复制实现。

本修复只影响构建验证脚本，不改变客户端监听、用户配置、节点或系统网络。公开发行前取消失败的 v5.0.9 构建，保留不可变标签，将正式版本递增到 v5.0.10，不通过修改旧标签或移除检查来发布。
