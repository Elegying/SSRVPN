## 问题二：规则正在初始化时启动被判失败

用户报告的关键时间线：

- 12:02:30.364：TUN 网卡创建警告，提示重试 1/3。
- 12:02:30.591：TUN 开始监听，随后多个规则 Provider 开始初始化。
- 同秒：客户端报告“分流规则尚未就绪”。
- 12:02:31–32：核心仍有规则匹配及转发日志。
- 12:02:34：核心停止。

网卡错误文字具有 Windows 特征，按 Windows 启动路径核对。报告没有完整的启动起点、客户端版本和规则就绪快照，不能证明每一份规则当时均正常，也不能把转发日志视为外网成功证明。

发现并修正的代码问题：

1. Windows 原总轮询预算为 15 秒，网卡身份查询也在其中，网卡重试可能耗尽规则初始化可用的时间。TUN 预算改为 45 秒，普通系统代理仍为 15 秒；采用单调时钟，健康成功即返回，仍检查取消、进程退出和所有必要规则。
2. “规则尚未就绪”原本会触发规则版本回退/拒用。移除此模糊条件：只有明确文件缺失、空文件或规则解析失败等证据才能触发规则恢复。
3. 对用户的解释区分“尚未准备好”和“文件加载错误”，不再仅凭未就绪声称配置无效或文件损坏。

测试覆盖延迟初始化成功、永不就绪的有限预算、即时成功、检查中取消、核心退出、规则不被误拒用，以及明确坏规则仍可恢复。
