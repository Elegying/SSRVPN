## 范围与维护者确认

- 2026-09-18 维护者明确保留 Android 国内应用绕过 VPN 的例外。这些 UID 的两种地址族
  均由系统联网，不能声称它们经过核心，也不能声称网站强制代理能覆盖这些 UID。
- Android 还排除了 ADB 系统包；通用浏览器不加入国内应用排除名单。
- 进入核心且命中 PROXY 的访问不得因目标地址族失败转为 DIRECT。
- 系统代理只能约束遵守代理设置的应用；其余应用、系统解析不属于全机接管。
- 维护者进一步确认：核心崩溃或客户端退出后不再接管。不增加系统级断网封锁，
  保留释放 TUN、恢复系统网络的行为；运行期 PROXY 不降为 DIRECT 与退出后恢复联网
  分别验收，不能将主动恢复网络算作规则泄漏，也不能把系统代理称为全机接管。
- 没有可达节点入口时客户端不能创造连接；IPv4-only 出口不能直接抵达 IPv6-only 目标。
  节点入口地址族与节点出口地址族分别验证，不用其中一个推断另一个。

## 实际数据流（修改前）

```text
Android 排除 UID ───────────────────────────→ 系统物理网络（双栈例外）
Android 其他 UID / 桌面 TUN → 虚拟接口 → DNS 映射 / 嗅探 → 规则
桌面遵循系统代理的应用 → mixed / SOCKS ────────────────┘
  规则 → DIRECT → 直连解析器 / dialer → 绑定物理出口 → 目标
       → PROXY  → 已选代理 → 本地目标解析 → 固定 IPv4 候选优先
                         → IPv6 候选 → 原始域名远端解析 → 同一代理协议
```

| 层 | 代码入口与已核实行为 | 缺口 / 限制 |
| --- | --- | --- |
| 配置 | `packages/ssrvpn_shared/lib/services/clash_config_generator.dart` 总是 rule 模式；全局通过末尾 MATCH,GLOBAL；用户手动规则在通用规则前 | Android 应用规则更早；系统排除 UID 不经过规则 |
| DNS | 同文件设置顶层和 DNS ipv6=true，但只提供 IPv4 fake-ip-range | 三端固定源码 `dns/middleware.go` 在 fakePool6=nil 时对普通 AAAA 返回空答案；不能据开关判断双栈 DNS |
| DNS 出口 | respect-rules，直连解析器和节点入口解析器独立；通用 DoH 经 PROXY | 默认 bootstrap 及通用 DoH 地址均是 IPv4；纯 IPv6 物理网无 NAT64 时需独立验证 |
| 嗅探 | HTTP override=true，TLS/QUIC 不覆盖目标；保留 SniffHost | IPv6 字面目标没有可靠域名时不能转换为 IPv4 |
| 规则 | 双栈手动 IP 规则；域名、国内规则、代理兜底；PROXY/GLOBAL 组不插入 DIRECT | 私网路由排除的 IPv4 目标可在进入核心前绕过；不能把规则级证明当系统级证明 |
| 代理地址 | `native/proxy_traffic/target_address.go` 在 resolveMetadata 后执行，跳过 DIRECT/内部 DNS；最多 4 个 A、4 个 AAAA、原域名 | 固定 IPv4 优先、同步解析最多 2 秒；首个拨号可耗尽总预算；最后一个候选被原重试循环重复使用 |
| TCP | 三端 patch 的 `tunnel/tunnel.go` 在同一选定代理上拨号并重试 | 部分协议没有目标连接确认；NeedHandshake 分支可能在重试前写入应用预读数据，必须检查不可重放边界 |
| UDP | 同处 ListenPacketContext、sender 映射 | 创建 UDP 关联不等于目标可达；不可据此学习 IPv6 能力或把无应答归因于地址族 |
| DIRECT | 上游 dialer 支持双栈并发，但带真实 DstIP 时可能固定单一地址 | 当前 Windows 候选只修复可定位的 TCP bind6 后有域名时补试 A；非三端完整策略 |
| Android | VpnRouteInstaller 始终安装 ::/0 与 IPv6 地址；VpnAppExclusionInstaller 排除国内 UID；protect 避免核心出口回环 | 不能取消获授权的 UID 例外；停止 VpnService 会释放接管 |
| macOS | 平台 TUN 显式 inet6、auto-route，strict-route=false；runner 保存原 DNS 后启动并恢复 | active_network_device 只查询 IPv4 默认路由，active_physical_network_device 在 IPv6 部分前退出，纯 IPv6 接入有已确认的代码缺口 |
| Windows | TUN strict-route、IPv6 地址；运行探测使用 IPv4/IPv6 目标与网卡身份；恢复记录按所有权处理 | Mac 上的宿主测试和交叉编译不能验证 Windows 路由/WFP 行为 |
| 应用自身请求 | DirectFetcher 有脱离 TUN 的物理网卡直连用途及 Fake-IP 安全回退 | 当前 Fake-IP 识别只含 IPv4；增加 IPv6 假地址必须同步审计订阅地址安全链，不可把 ULA 整体放行 |

三端固定源码身份来自 `native/proxy_traffic/sources.json`，已读取对应提交的
`config/config.go` 和 `dns/middleware.go`，不是根据最新上游文档猜测。

## 验收矩阵与证据分层

矩阵维度：物理接入 IPv4-only / IPv6-only / 双栈；节点入口 IPv4 / IPv6 / 双栈；
节点出口 IPv4-only / IPv6-only / 双栈；目标 A-only / AAAA-only / A+AAAA / 字面 IPv6；
DIRECT / PROXY / 手动覆盖；TUN / 显式代理 / 系统代理。

不要求物理上无可达路径的组合成功，但要求有限失败、其他连接可用、无代理降为直连。
每种生成配置需通过三端固定版本解析验证。成功证据要包含完整应用层响应和真实出站，
失败证据要包含直连哨兵未收到流量；不能只查配置字符串、TCP connect 或延迟。

必须单列：DNS A/AAAA 一侧超时、代理无目标确认、首写失败不重放、错误 TLS 证书拒绝、
IPv6 Fake-IP 安全解析/重定向/订阅不回归、连接取消与总预算、恢复后双栈路由所有权。
不采用阻塞式外部 IPv6 能力探测；不能从一次失败永久标记节点不支持 IPv6。

### 新增实现

- 配置补充独立 IPv6 Fake-IP 池，与 TUN 接口地址分离；订阅安全解析只识别这个池，
  继续拒绝私网、任意 ULA 和字面 Fake-IP。补充 IPv6 bootstrap 和代理 DoH 入口。
- 共用 DNS 查询在一族已有结果时只短暂等待另一族，保留取消及总预算。
- TCP 首写一旦涉及应用数据，错误后不再重放到另一个地址。
- 有目标连接确认的代理保留地址族候选和短期实际响应偏好；缓存只针对节点+目标+协议，
  不以 TCP 握手成功认定节点具备 IPv6 能力。
- 无可靠目标确认的 SS/SSR/Trojan/VMess/VLESS/Hysteria/Hysteria2/TUIC/AnyTLS TCP
  保留域名给已选代理解析，不再提前固定本机解析出的 IPv4。字面地址、hosts、内部请求
  不改变。UDP 没有收到响应不能据此推导目标可达，不复用 TCP 学习结果。
- DIRECT 在发送应用数据前发生地址族拨号失败时，可在原 DIRECT 出口补试另一族；
  保留原接口约束、回环检查、取消和总预算。
- macOS DNS 事务补充只有 IPv6 默认路由的物理接口识别。
