# SSRVPN 组合流程审查（2026-09-16）

本轮承接安卓自身 VPN 下 HTTPS 订阅 Fake-IP 修复，检查网络请求在多阶段、超时、取消和备用地址切换时的实际资源释放。修改仍在本地工作树，未提交、未发布，也未安装到设备。

## 已复现并修复

### 三端更新下载：超时切换备用地址时，旧请求仍可能等待响应

涉及 `SSRVPN_Android/lib/services/update_service.dart` 和桌面共享的 `packages/ssrvpn_shared/lib/services/update_service_download.dart`。

原实现对 `client.send` 设置 Future 超时，并在响应迟到后取消响应流。但在服务器始终不返回响应头时，这种处理不会主动中止旧请求。使用自建客户端时最终关闭客户端可以兜底，但切换备用地址期间旧请求仍可能存在；调用方提供的客户端不会被下载器关闭。

修复复用现有 http 包的 `AbortableRequest`：每个地址有自己的取消信号，在该次尝试结束时发出。保留调用方客户端的使用权，保留原有迟到响应清理、文件清理、大小限制和摘要校验。

回归测试先在旧实现上失败：备用请求开始时，未结束的旧请求数量为 1，预期为 0。修复后通过。另外为安卓和桌面各增加真实本地 HTTP socket 测试，验证等待响应头期间超时或取消后，服务器确实观察到连接关闭。测试只将测试请求转到 loopback，不访问用户订阅，不改变生产 URL 校验。

安卓更新测试文件包含 widget 测试，Flutter binding 会替换 HttpClient 为固定 400 响应；真实 socket 用例显式创建 dart:io 客户端，避免把测试替身行为当成产品网络行为。

### 桌面订阅：兼容身份重试时，总时限结束没有同步中止连接

涉及 `packages/ssrvpn_shared/lib/services/desktop_subscription_fetcher.dart`，macOS 与 Windows 共用。

原实现只在进入直连流程时计算一次剩余时限。服务器拒绝首次请求后，兼容身份重试仍沿用该时限；外层批量时限先结束时，没有给 `control.wait` 提供中止回调。因此调用方已收到总时限错误，重试连接仍可能等到自己的超时才关闭。

修复给整个直连兼容流程添加独立的子取消信号，用户取消和外层总时限均能中止当前连接，退出流程时解除监听并清理。不会把批量超时改写成用户取消，不改变解析、TLS 或代理选择策略。

新增真实本地连接用例：首次请求延迟返回 403，第二次请求不返回响应；总时限结束后要求第二条连接及时关闭，并断言父级用户取消信号仍未被取消。该用例在修复前因等待连接关闭超时而失败，修复后通过。

## 本轮检查但未发现相同遗漏的路径

共享规则下载为每次请求创建独立的代理客户端，在 finally 中关闭，当前所检查的超时路径没有与更新下载相同的跨备用请求残留问题。这仅是该资源清理路径的源码结论，不代表规则发布、三端实际路由和所有网络条件均已验证。

## 以后采用的审查方法

1. 按用户完整操作追踪到实际网络资源：解析结果、连接地址、TLS 主机名、代理出口、响应解析、落盘、页面反馈，不用单组件通过替代端到端证据。
2. 每条备用或重试路径同时检查三个问题：是否共享总时限、上一请求是否结束、取消能否到达当前底层请求。
3. 故障注入覆盖发生位置：DNS、连接、TLS、等待响应头、缓慢响应体，以及第一次成功或失败后的下一阶段。
4. 失败验收既检查错误分类，也检查连接释放、临时文件清理、已有节点保留、其他订阅继续更新和用户可重试。
5. 测试要观察行为。模拟客户端适合验证调用顺序；真实本地 socket 适合验证连接中止；安装后的自身 VPN 场景仍需要真机验收。
6. 新问题先写能在旧实现上失败的测试，再修改生产代码；报告区分源码结论、自动化、本机网络、安装实测和公开发布。
