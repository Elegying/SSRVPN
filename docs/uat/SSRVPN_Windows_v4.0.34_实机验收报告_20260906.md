# SSRVPN Windows v4.0.34 实机验收报告

> 执行日期：2026-09-06 至 2026-09-07，Asia/Shanghai。执行人：Windows 本机 Codex。
> 本轮为正式安装版实机验证，测试节点由维护者提供。本文不包含节点地址、密码、订阅或本机用户名。

## 结论与修复交接

本轮已发现一项明确失败：**F-01，P2，复制的诊断报告仍包含双反斜杠 Windows 路径中的本机用户名**。
这违反 C-10 的脱敏要求，因此不能据本轮报告放行 Windows 完整验收。修复由 Mac 端 Codex 接手；
本分支仅提交报告、脱敏证据和复现程序，没有修改客户端实现。

系统代理 20/20 轮连接、断开与资源清理通过；TUN 和系统代理的数据通道、模式切换、
GUI 异常退出后的清理、同版本覆盖安装、卸载保留数据与正式包重装均取得实机证据。
其余范围按下表单独标记；自动化通过、网站返回 HTTP 响应或配置正确都不替代完整实机功能验收。

### 测量环境修复与证据口径

开始时自动化宿主未持有管理员令牌，而 SSRVPN 以管理员运行，导致界面操作受阻。
修复了本机 Codex 管理员启动方式，并核对实际进程令牌后继续；这是执行环境问题，不是 SSRVPN 缺陷。
测试没有降低 UAC、杀毒软件或防火墙保护。本机原有管理员自动批准策略使 UAC 同意/取消弹窗无法实际出现。

另有两项探针误差在定稿前纠正：

- MSIX 宿主内直接读取 HKCU/HKU 的代理值与原生会话不一致。最终系统代理结论使用
  **WMI `StdRegProv` 对当前用户 HKU 的读取**；20 轮数据全部使用该口径。
  早期直接注册表读取的 `ProxyEnable=0` 不作为系统代理失败证据。
- Windows PowerShell 5.1 对未声明字符集的控制器 JSON 默认解码造成中文节点名比较失败。
  改为对响应字节显式 UTF-8 解码，并与 PowerShell 7 和原始节点偏好交叉核对。
  该时段仅节点名相等字段无效，HTTPS、PID 和端口采样仍有效；不把它认定为应用切换节点。

## F-01：诊断复制遗漏双反斜杠路径中的用户名

**级别：P2；确认状态：实机复现 + 当前同源实现最小复现；验收影响：C-10 失败。**

2026-09-06 23:15:01，在系统代理已连接时，打开“订阅 → 运行日志”。诊断结论为
“运行正常，未发现异常”，并标示运行记录已经脱敏。首次复制显示“复制失败，请重试”，
剪贴板 sentinel 保持不变；再次点击后约 23:16:03 显示成功，实际读回报告长度 3,518 字符。
对读回文本进行无正文扫描，命中当前 Windows 用户名。

最小复现步骤：

1. 在 Windows 正式版连接一个有效节点，使 Mihomo 产生加载 MMDB 的运行日志。
2. 打开订阅页的运行日志，生成诊断并复制到剪贴板。
3. 实际读回剪贴板，搜索当前 Windows 用户名；不要直接上传原始内容。
4. 检查 `Load MMDB file` 行，双反斜杠路径仍保留用户名。

实际拷贝内容的**人工二次脱敏片段**如下。`[USER]` 是验收时额外替换的，不是客户端已经完成脱敏：

```text
结论：运行正常，未发现异常
最近运行记录（已整理、已脱敏）
... msg="Load MMDB file: C:\\Users\\[USER]\\AppData\\Local\\Programs\\SSRVPN\\bin\\ssrvpn/ge
... log entry truncated ...
```

预期：普通路径、转义路径及截断附近的路径都不应含本机用户名。
实际：普通单反斜杠路径能脱敏，Mihomo 输出的双反斜杠路径漏过。
本轮没有在复制报告中命中提供的节点 URI 或节点主机，不据此推断不存在其他泄露边界。

定位依据：

- `packages/ssrvpn_shared/lib/utils/log_redactor.dart:126` 的 `_windowsHomePattern`
  仅匹配单个目录分隔反斜杠；替换发生在同文件约第 234 行。
- `packages/ssrvpn_shared/lib/models/app_diagnostics.dart:592` 使用共享脱敏方法处理原始日志。
- `packages/ssrvpn_shared/lib/widgets/app_diagnostics_view.dart:112` 已执行剪贴板写入及读回比较。
  因此本轮首次失败后的提示是如实报错，不能重述成旧版“复制假成功”缺陷。

最小复现程序见 [reproduce_redaction.dart](evidence/windows-v4.0.34-20260906/reproduce_redaction.dart)。
在仓库根目录执行：

```sh
dart --packages=.dart_tool/package_config.json docs/uat/evidence/windows-v4.0.34-20260906/reproduce_redaction.dart
```

当前结果为普通路径 `normal_username_leaks=false`、转义路径 `escaped_username_leaks=true`。
共享诊断/脱敏现有 62 项测试全部通过，说明现有覆盖没有阻止这一真实输入形式。

建议 Mac 端修复共享路径脱敏对转义分隔符的处理，增加普通路径、双反斜杠、混合分隔符、
大小写目录名、截断边界和复制报告的回归；随后使用新 Windows 正式/候选安装器重做剪贴板读回扫描。
不得只凭新增单元测试通过就把本实机失败关闭。

## 数据通道和模式切换

- TUN 智能 → 全局 → 智能：分别等待核心重建并读取稳定态；UI、偏好、控制器一致，HTTPS 204。
  转换中的单次画面/旧状态不作为稳定状态。该结果不替代不同节点之间的热切换。
- TUN → 系统代理：TUN 消失，系统代理启用，本地显式 HTTP 代理的 HTTPS 请求正常。
- TUN 异常结束：GUI PID 7820、核心 22076 的连接状态确认后，仅结束已核验路径的 GUI。
  8 秒后无 GUI、核心、端口或 TUN；重开后可连接。没有直接删除网卡或杀死核心来冒充 guardian 恢复。
- 系统代理异常结束：已连接状态下仅结束 GUI，随后代理恢复为关闭且核心/端口清理。
