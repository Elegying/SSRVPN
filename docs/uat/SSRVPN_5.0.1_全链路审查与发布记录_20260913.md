## 本轮确认并修复的问题

### P2：其他 VPN 占用被误报为整批解析失败

无线手机前台为正式包 `com.ssrvpn.android`，活动 VPN 由预览包 `com.ssrvpn.android.preview` 持有。原生实现直到 DNS 完成、准备 TCP socket 时才检查其他 VPN；解析阶段受另一 VPN 的策略影响时，会先返回“解析失败”。用户切回预览版后确认测速正常，排除本次节点集体失效。

现将检查提前到解析前，返回独立结果码 -15，三端共享文案为“其他VPN占用”，使用中性色且仍允许选节点，不按远端节点故障排序。socket 创建前的再次检查仍保留，以处理测速中途 VPN 所有权变化。普通 VPN 连接与解析路径不变；没有调整全局 DNS 或关闭用户 VPN。

新增失败码传递/文案/排序回归，并在现有 Android 桥接门禁中约束“其他 VPN 判定早于 DNS”。

## 证据边界

- 独立账户接口诊断曾被自动审批拒绝，因为请求需要向外部接口发送节点凭据；未执行也未绕过。后来在本轮正常客户端连接/断开操作中看到两张账户统计卡刷新，补上用户界面观察，但未宣称独立 API 协议终验。
- 本轮原始截图含真实出口和账户数据，仅用于本地界面观察，不提交到公开仓库。
- 固定刷新率/自动模式的最终输出受系统合成器、OEM、温控控制；Windows/ProMotion高刷新实机与长期功耗仍没有新证据。
- 自动化测试、CI 原生安装/卸载、用户真机体验和公开下载是不同证据，不互相替代。
