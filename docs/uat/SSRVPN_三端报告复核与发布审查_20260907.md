## 发现与修复

1. **代理累计口径**：PR #215 已合入主分支 `78ef0a4d3d94419ef6da68298efff895b2589920`。
   三端采用实际代理出口计数，排除 DIRECT、REJECT 及内部链重复，短连接和后台累计保留，
   新会话隔离旧回调；Android 常驻通知同源。账号用量与服务端计费不变。
2. **Android 模式重载**：内部停止与用户手动停止分别传递意图，修复在线切换模式后不重连。
   原生缺省仍为手动停止，通知/磁贴主动取消继续优先。已完成本机回归和真机双向验证。
3. **Windows F-01 诊断用户名泄露**：原报告最小复现已再次证明普通路径不泄露、转义路径泄露。
   共享脱敏器改为一次匹配 Windows/Unix 用户目录；Windows 支持重复、混合分隔符和目录名大小写，
   保留后续文件上下文，截断在用户名中时同样隐藏已出现部分；Unix 原有用户名匹配范围保留。
   原始复现修复后两项均为 `false`。先运行新增回归观察失败，再修复；诊断视图的复制测试
   实际核对传给平台剪贴板通道及读回的最终报告，确认没有测试用户名。
4. **发布准备主机遗漏**：普通 CI 与 Release 的固定核心重建已采用 macOS；Prepare Release
   仍使用 Linux，会使跨宿主 Android 二进制摘要校验不具备保证。其主机同步为 `macos-15`，
   增加工作流守卫，保留原固定源码、工具链和 SHA-256 校验，不放宽任何发布条件。
5. **Swift 扫描与维护门槛**：PR #215 的完整最终 CI 已成功，含 Swift security-extended、
   三端构建、Windows 安装器冒烟及安全分析；Windows 生命周期行为覆盖下限为 51%，文档已同步。

Windows 首次复制失败后显示失败提示，第二次成功且读回得到报告，这是现有复制结果校验
正确工作，不作为新的“假成功”缺陷。报告中的宿主权限、注册表读取口径、字符集探针及镜像
输入问题均已与产品缺陷分开核对，没有因此改动 VPN 或系统安全策略。
