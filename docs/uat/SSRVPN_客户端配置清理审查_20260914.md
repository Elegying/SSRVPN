# 客户端配置清理审查

日期：2026-09-14。范围：Android 连接编排、首选节点快照与临时配置清理；补查桌面连接事务和手动规则写入调用链。

## 发现与修复

原 discardPreparedConfig 在查询不到原生会话时，只根据 Dart 层是否运行判断是否删除。原生状态可能迟到或通道查询失败，此时删除配置会与原生认领配置发生冲突。

修复后仅在原生返回有效的明确空闲状态、没有受保护配置，且本地也未运行或切换时清理。状态未知、查询失败、仍在运行/过渡或存在受保护路径时保留文件。清理期间保留 prepared 集合中的引用，结束后才移除，避免异步查询期间被其他本地清理路径当作无用文件。

文件系统清理异常现在只记录延后清理，不覆盖连接编排 finally、端口重试或首选节点取消操作的原始结果。原生快照撤销与设置提交的失败处理未被改为忽略错误。

代价是异常状态下保留临时文件，后续沿用现有安全清理流程；这些文件仍位于应用私有配置目录。本轮没有引入定时删除或在无法证明原生空闲时强制清理。

## 回归设计

- 原生通道抛错、返回空值：配置必须保留。
- 原生明确空闲：未认领配置仍应删除，不能把所有清理直接禁用。
- 原生已经认领配置：保留原有保护断言。
- 将临时目录设为不可写：删除失败不能抛出并覆盖连接结果，文件保留且有诊断日志；测试 finally 恢复目录权限。
- 旧测试以空状态模拟“空闲”不再成立，已改为有效空闲快照，保留删除成功断言。首次新增测试还发现空闲快照不能携带运行会话代际，已修正测试数据，未放宽生产状态解析器。
