# macOS TUN 规则目录缺失修复

5.0.3 的特权运行脚本仅复制两个旧版 MRS 缓存，新版配置引用 providers/bundles/2.0.1/*.yaml，因此切换到独立 TUN 运行目录后缺少实际规则文件。用户报告中的“分流规则尚未就绪”与该路径一致；本次没有在用户的管理员授权 TUN 会话中复现。

修复按同一份配置字节解析 rule-providers，授权前检查实际文件，授权后复制并校验 SHA256，启动器再把已验证的完整目录交给 TUN 核心。目录、版本及相对路径保持一致，只复制本次引用的文件。缺失或空文件提前报告路径；旧版 MRS、内联规则兼容。同步更新特权脚本哈希，保留全部就绪与恢复检查。诊断将规则缺失/未就绪归为配置错误，不再提示无法访问核心。

验证：TUN 专项 41 项、诊断 23 项、原生脚本门禁 25 项、DNS 事务 25 项通过；变更文件 Dart 静态分析、脚本语法、ShellCheck、diff 空白检查通过。真实 Mihomo 测试从迁移后的版本目录加载全部内置规则，逐项验证文件内容及 provider 非零规则计数；该测试明确禁用 TUN/DNS，不改本机路由。测试也验证缺文件、空文件、路径越界、授权准备后内容变更及旧格式兼容。

旧的静态门禁只检查两个旧缓存文件，未验证新版规则目录，已替换并新增上述行为回归。本机 Xcode 许可尚未接受，测试通过临时 xcrun 包装器使用既有 Command Line Tools；未代接受许可。初次新增测试的 Dart 字符串转义与严格类型问题已修正，最终记录为 /tmp 中 final 日志及 artifacts/macos-tun-rule-fix-20260915。

维护者已授权以 5.0.4+5004 三端同步发版，按受保护 PR、精确 main CI 和 Release 流程执行。正式发布状态以 GitHub Releases 为准，版本号不代表已发布；本次未执行管理员 TUN 实连验收。不能把目录与内核规则加载回归等同于完整 TUN 实机连接成功。
