# 输入与订阅网络边界审查

日期：2026-09-14。本轮改从 URL 输入、订阅重定向和网络访问范围审查。

## 订阅重定向的私网边界

原地址策略允许用户明确输入 LAN/loopback IP，但重定向目标也被当作这种明确输入，导致公网订阅服务器可以借重定向请求本机或其他私网服务。

新增共享重定向策略：先执行已有 URL/协议与 HTTPS 防降级检查；若目标是非公网 IP，必须与当前来源的主机及端口一致，否则抛出地址安全错误。公网 IP/域名跳转仍允许，域名解析继续执行已有公网地址校验与地址固定连接。用户直接输入内网订阅保持兼容，同一内网端点内的相对跳转也保持兼容。

策略接入三条真实下载链：DirectFetcher、桌面常规 HTTP、Android 订阅请求。地址安全错误继续沿用不可降级重试的处理方式。

回归包含 loopback、LAN、链路本地、IPv6 和 IPv4 映射 IPv6 私网目标；用两个实际回环 HTTP 服务验证重定向被拒绝时第二个服务收到零请求，安卓适配器验证仅请求原公网地址。此边界并非禁止用户有意访问自己填写的内网订阅。

## 手动规则的 URL 兼容性

原解析器拒绝网址任意位置的百分号，导致合法编码路径或查询参数无法提取域名。现在只拒绝 authority 中的歧义编码，保留 IPv6 zone 拒绝；正常路径/查询编码可以使用。实际规则生成只输出主机，不把路径或查询带入配置。新增 DNS 主机总长度限制 253 字符，各标签原有限制继续保留。

测试覆盖编码路径、编码查询、编码主机拒绝、IPv6 zone 拒绝及超长域名；生产配置真实内核流量测试改用带编码路径的手动代理网址，以验证不只是解析器单独返回正确字符串。
