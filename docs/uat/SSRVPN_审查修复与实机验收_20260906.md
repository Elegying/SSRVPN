# SSRVPN 审查修复与实机验收（2026-09-06）

本轮以正式 v4.0.34 对应的最新主分支为基线，迁移并修复本地未交付改动。
应用版本保持 `4.0.34+4034`；交付范围为源码提交、受保护 PR 和主分支同步，不创建标签、
不执行 Prepare/Release、不上传核心 Release 资产、不更新 GitHub/OSS 安装包。
PR：[#215](https://github.com/Elegying/SSRVPN/pull/215)。云端最终检查及合并信息待验收完成后补齐。

## 审查问题与处理

| 问题 | 修复与验证 |
| --- | --- |
| 桌面首页把 DIRECT 包含在累计中 | 新增认证 `/ssrvpn/traffic`，按实际出口类型计数；共享桌面采样器改用此接口，不再为三个数字读取完整连接历史。原核心全局 API 保持兼容。 |
| Android 首页和通知使用应用 UID 流量 | 首页采用同一代理计数接口；通知改用原生 Bridge 的同源计数，排除直连、应用自身查询及内部代理链重复记账。 |
| Android 已连接时切换模式会停止后不重连 | 真机复现配置重载停止被标记为手动断开；桥接请求显式区分内部重载和用户停止，默认仍为手动停止，通知/磁贴取消意图保持优先。先补原生标记回归并观察失败，再修复；最终同机全局→智能、智能→全局均重新启动成功，API 会话代际递增，国内外 HTTPS 恢复，累计重新开始。 |
| 短连接、后台与重连统计边界 | 原子会话累计保留已关闭连接；新会话隔离旧连接的迟到回调。新增 Go 分类、TCP/UDP、并发、旧会话、API 认证回归，以及 Android 采样重置行为验证。 |
| Swift 安全扫描缺口 | 现有必需的 macOS 原生检查先独立执行 XCTest，再固定 arm64、独立 DerivedData 运行 Swift CodeQL，避免把测试注入和扫描构建耦合。远端扫描结果尚待确认。 |
| Windows 生命周期覆盖不足、文档写旧门槛 | 增加并发停止、清理失败重试、待恢复日志、未知进程所有权四类行为回归；文件覆盖率从 350/700 提高到 358/700（51.14%），门槛提升至 51%，同步测试规范与路线图。 |
| 生命周期热点继续增长 | 为 Windows 生命周期增加 1763 行规模上限，维持现有所有权及事务边界；复杂度仍是维护成本，不用机械拆文件冒充风险消失。 |
| 更新弹窗测试在机器高负载下串联失败 | 辅助函数由 10 秒等待提高为有界 30 秒，并在未达到预期状态时直接断言失败，避免后续用例承接不完整弹窗。完整 Windows 套件已重新通过。 |
| 新核心无法在未发版时由 CI 取得 | 固定源码、Go 归档长度及 SHA-256、NDK 版本，从源重建后仍严格核对资产摘要；普通 CI 只保存工作流制品。 |
| Android 重建受机器路径影响 | 固定 gomobile 本地模块路径，并使用 `-s -w -buildid=` 排除 NDK 调试路径及构建标识。直接对比本地/CI ELF，运行代码与数据段一致，原差异为调试信息及标识；远端 CI 34043645578 核心来源检查已通过，三端资产摘要全部匹配。 |

私家车节点成功延迟显示为 24–39 ms 的既定策略按明确要求保留，未修改策略实现、调用语义或排序行为。
账号用量卡仍与本机代理累计分开，不改变服务端计费或账号配额。
