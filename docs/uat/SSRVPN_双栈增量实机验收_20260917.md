## 实机发现与修复

第一候选在 Mac 高档玻璃下展开日志并滚动时，卡片绘制到列表视口外，覆盖弹窗标题及底部。
根因是共享取样路径新建 `LiquidGlassLayer` 后，嵌套卡片仍可能继承外层弹窗的
`LiquidGlassBlendGroup`，形状在外层绘制，绕过中间滚动区域的裁剪。

在共享 `SsrvpnLiquidSurface` 的捕获路径为每层增加独立、blend=0 的形状组，
保留共享壁纸纹理与光学参数，不降低效果，不新增捕获循环。
重新构建安装后，Mac 高档与中档日志滚动、技术详情展开及宽窄窗口检查未再观察到该越界；
安卓最终候选展开并滚动 13 条记录，截图中的卡片正确裁剪在日志视口内。
窗口拖拽过程中一次点击触及遮罩导致弹窗正常关闭，宽窗口是在重新打开后检查，
不将这一操作写成“弹窗全程保持打开连续缩放通过”。

## 网络验收

初始路由器屏蔽 IPv6，随后维护者开启。两端 Wi-Fi 均取得公网 IPv6 地址，未主动断开 Wi-Fi。
带 `curl -6` 的域名请求可能得到核心的 Fake-IP，不能单凭请求成功断言公网 IPv6 出口正常。
因此补充从核心 DNS 查询获得真实 AAAA，并固定该 IPv6 目标、保留域名 TLS 校验的请求。

| 项目 | 实际结果与边界 |
| --- | --- |
| Mac 运行配置 | API 显示 IPv6=true、TUN enabled、gVisor、IPv6 TUN 地址；生成配置 DNS IPv6=true，未含全局 IPv6 REJECT；认证流量接口包含新增诊断字段 |
| Mac 国内 IPv4 | 百度 HTTPS 200，约 0.145 秒 |
| Mac 国内真实 IPv6 | 固定百度公网 AAAA、保持域名 TLS，HTTPS 200，约 0.125 秒；实时核心日志确认该请求命中 DIRECT |
| Android 国内真实 IPv6 | USB 转发至手机 SOCKS5，固定同一公网 AAAA、保持 TLS 主机名，HTTPS 200，约 0.177 秒；此证据是手机代理/出口链路，不冒充浏览器 UID 的 TUN 路由验证 |
| 两端普通海外代理 | Cloudflare HTTPS 200，Mac 约 0.532 秒，Android 约 0.692 秒；Gstatic 请求也返回 204 |
| Android 真实浏览器 | Edge 实际加载 Example Domain，页面可见，无浏览器错误页；这是浏览器访问证据，未据此判定其最终 IP 地址族 |
| Android 原生状态 | 界面已连接；诊断核心、API、Flutter/原生会话一致、TUN、Bridge、socket protect 均通过；系统 TUN IPv6 地址存在 |
| 纯 IPv6 海外目标 | 经当前节点访问 Cloudflare IPv6 字面目标发生 TLS 连接失败，路由器开启前后均未成功；不据此认定节点全局不支持 IPv6，也不认定路由器是根因 |
| 失败隔离 | 上述纯 IPv6 请求失败后，普通代理 HTTPS 继续成功，两端会话未被自动断开 |

腾讯站点返回 HTTP 501，只记为 TLS/HTTP 通路可达，不记为页面正常。
早期绑定物理接口的域名探测遇到超时，因域名可能解析为 Fake-IP，未用它判断真实 IPv6 出口；
以随后固定真实 AAAA 的请求和核心 DIRECT 记录为准。
