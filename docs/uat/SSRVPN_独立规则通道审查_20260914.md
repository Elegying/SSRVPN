# 独立规则通道实施与审查记录

日期：2026-09-14。分支：`codex/independent-routing-updates`。

本记录描述开发验证，不代表客户端正式发布或三端实机验收完成。

**后续调整：** 用户随后要求安卓应用名单恢复最高优先级，国内应用从系统 VPN 排除、国外应用强制代理。本报告下方的“手动规则优先于应用名单”等描述记录初始方案，已被该调整取代；当前契约以 ADR-017 和产品要求第 36 条为准。后续验证结果见文末。

## 已实现行为

- 订阅仅提供节点，上游路由、DNS、规则集及其他配置不进入客户端策略。
- 用户手动规则优先；安卓应用名单其次；自动代理/GFW、国内域名/IP、未知代理随后。通用浏览器按目标分流。全局模式也保留用户手动例外。
- 公共规则、安卓直连名单、安卓代理名单独立计版，统一签名快照保证一致性。桌面端不下载应用名单。
- 每次启动首次连接成功两分钟后检查一次，提前断开取消，不轮询。下载及失败静默；完整校验后持久化，下一次连接启用，不主动断开当前连接。
- 公开规则仓库与源码仓库分离；客户端只有签名公钥。规则源每日自动同步，异常数据停止发布。

## 多轮审查与修复

| 审查范围 | 发现与处理 |
| --- | --- |
| 优先级与订阅边界 | 全局模式原本可能绕过手动规则，改为规则模式保留手动例外后交给 GLOBAL；自动 DNS 策略不得覆盖手动策略。补充普通、大型订阅与缓存夹带测试。 |
| 安卓应用分流 | 系统排除国内应用会绕过手动规则，因此停止该排除；增加本地 UID/包名查询桥接，查询失败回到目标规则。 |
| 更新事务与输入校验 | 先验签，再检查清单摘要、组件版本、文件摘要/大小/数量/语法；独立目录完整落盘后才替换活动清单；移除先删旧文件的写法。 |
| 离线恢复 | 移除未签名 HTTP provider 回退；本地完整基线准备失败时使用保守内置规则，避免依赖远端才能连接。 |
| 真内核时序 | 控制 API 就绪不代表规则已经加载。连接就绪检查增加所有本地 provider 条目数检查，避免首次请求落入未初始化规则。 |
| 观察结果准确性 | 用户将出口查询目标设为直连时，不把直连 IP 归属到代理节点。 |
| 负载与故障 | 大规则解析/更新校验移入后台 isolate；调整专用规则解析数量上限，不放宽订阅解析限制。包名查询有并发、消息长度和时间上限。 |

- 完整验证入口的静态检查、格式/ShellCheck、核心资产、秘密扫描、性能冒烟与发布工具 433 项测试通过。发现失败后修正并从相关阶段复跑，未降低覆盖率门槛。

从匿名公开下载地址独立取得版本索引、不可变快照清单和全部 10 个数据文件，签名、摘要、大小、条目数及内容校验通过。线上版本仍为 `2.0.0`，无变化不产生新版本。工作流已实际运行成功，未来定时触发仍需持续观察，不能将一次成功视为长期可用性保证。

客户端尚未提交、合并或正式发版。本机无法替代 Windows 原生运行与三端实际网络验收。Android 10 以下、共享 UID、查询失败按目标分流；应用分身、特殊 OEM、无启动入口应用和浏览器需要实机确认。

实机应重点检查：手动规则覆盖应用名单、浏览器按域名分流、断网/坏更新保留旧规则、重连启用完整新快照、不同模式切换、休眠恢复与低端设备首次规则加载时间。成熟规则源不能保证每个目标在所有网络实时可达。

当前保留历史完整快照，避免清理正在被内核使用的文件；频繁更新会增加本地占用，尚未加入自动历史快照回收。后续回收必须在核心停止后进行，并保留当前版本及可恢复版本。


## 后续调整：应用名单优先

国内排除名单与连接配置绑定，磁贴启动和进程恢复读取同一版本；显式空名单不会重新启用旧内置名单。运行时识别的浏览器不会进入排除列表。国外应用 PROCESS-NAME 规则在智能和全局模式下均位于手动规则之前，桌面端无应用名单时保持手动优先。

首轮 137 项针对性测试及 Android 原生编译/单元测试通过，覆盖动态名单元数据、系统排除、浏览器排除、损坏元数据拒绝、双模式优先级及原生连接快照。最终回归：共享客户端 1,190 项、Android 297 项、macOS 321 项、Windows 302 项通过（Windows 7 项跳过），所有覆盖率门槛通过。Android 原生测试再次通过，其中排除名单测试 5 项、零失败；三端静态检查、格式、原生桥接守卫和文档一致性检查通过。真实 macOS 内核的智能、全局、离线回退三组流量验证通过，说明桌面目标分流未被本次应用规则调整破坏；不作为 Android 实机包名识别证据。规则仓库说明已同步，数据未改变，版本仍为 2.0.0。无三端实机验收或客户端发版结论。
