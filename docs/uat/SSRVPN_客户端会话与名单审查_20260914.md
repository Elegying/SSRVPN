# 客户端会话与应用名单审查

日期：2026-09-14。接续规则可靠性审查机制，重点检查客户端异步生命周期与实际启用路径。

## 修复

### 旧连接的规则下载跨越重连边界

原代码只检查 isRunning；断开后快速重连会让它重新为 true，旧任务因此可继续下载。并发调用还共用下载版本字段。

现在使用已有健康监控会话代际绑定这次更新，在异步边界重新检查，并增加单次任务锁，结束时清理下载版本和任务锁。断开重连、终止性连接丢失、服务释放及健康会话重置会使旧任务失效；重复调用不发起第二条更新链。没有增加轮询或自动重试。

已完成的原子磁盘提交不因随后取消而倒退；完整快照可在后续初始化被读取。取消保护阻止旧任务继续推进后续步骤和发布待用内存状态，不承诺撤销已经提交的磁盘数据。当前连接仍不会热切换规则。

### 应用名单下载容量与启用容量不一致

文件校验允许最多 200000 个条目，而名单交叉检查及实际读取仍使用普通 YAML 的 100000 个集合元素上限，导致较大名单被前一道检查接受、后一道拒绝。

交叉检查和实际启用统一复用受限名单读取函数，使用规则专用集合限制；读取时检查文件类型、大小、包名语法、重复/冲突和浏览器排除。读取与解析在 isolate 执行，普通订阅的资源限制没有放宽。

## 验证

针对性 119 项通过，覆盖三种会话终止边界、重复请求、100001 条合法应用名单、跨名单冲突、注入内容以及本地规则完整性。最终共享全量 1196 项通过，行覆盖率 87.77%，超过现有门槛。三端针对性连接回归共 221 项通过：Android 93、macOS 83、Windows 45（核心策略 10、生命周期/TUN 健康/错误报告 35）。四包静态分析无问题；服务职责边界、格式/ShellCheck、文档一致性和差异空白检查通过。真实 macOS 内核的智能、全局、离线回退三组流量验证通过。

三端测试首次从仓库根目录混合启动，导致 macOS 测试无法加载其内核资产；随后改从各自平台目录运行并全部通过。首次失败保留在 `/tmp/client-audit-platform-connection.log`，不计入产品通过证据。

## 继续保留的边界

- 本轮没有新增规则启动失败后的自动版本回退。它需要把规则确认成功、上一份可用快照、失败版本隔离，以及三端停止/重试和安卓磁贴恢复纳入同一恢复事务，不能把普通网络失败或 VPN 权限拒绝误判为坏规则。
- 安卓磁贴冷启动继续使用上次受保护的完整配置，新规则需经 App 生成下次配置后进入磁贴快照。
- 代码与自动化检查不是三端实机验收。本轮未安装新包或改变系统 VPN/代理配置，也未提交、合并或发布客户端。
