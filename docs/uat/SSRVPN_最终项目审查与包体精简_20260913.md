## 已落实的清理与修复

- 删除两张退休背景（共 1,582,011 字节），只打包已验收的深蓝背景。没有重编码当前图片或降低普通档材质清晰度。
- 删除旧背景的三个构建开关和材质诊断回退开关。保留资源加载失败时的基础背景、低性能档、高对比度和着色器能力兼容处理；这些是运行保障，不是历史版本副本。
- Android 删除未引用的桌面图标及旧 `liquid_lens.frag`。Android/macOS 的顶层资源从目录通配改为明确清单，共享背景同样明确列出。Windows 已使用明确资源清单。

- 全项目门禁发现主页文件超过 600 行限制。将现有开关组件移至同一 Dart library 的独立 part，行为和对外 API 不变。
- 清理旧发布/验收目录中的可再获取安装包、二进制副本，以及已确认的临时 macOS 回退应用。保留审查报告、日志、源码、当前核心资源、构建工具和已安装验收版。清理空间不等于客户端包体减少。

## 综合代码审查

本轮复核了未提交的共享渲染器缓存、节点测速排队、刷新率桥接、低档调度、订阅生命周期和三端 UI 接入。重点检查：几何形状/尺寸变化能使缓存失效，释放时清理 GPU 资源；测速任务在成功/异常/超时路径释放队列位置；异步订阅查询以 epoch 和 mounted 拒绝旧结果；前后台释放刷新率请求；正式构建默认不采集帧诊断。

安全与恢复仍沿用完整门禁检查，不因体积优化移除 TLS 验证、密钥存储、核心来源校验、DNS/代理恢复或签名流程。没有以依赖升级扩大本轮范围。

## 仍需保留的证据边界

1. Windows C++ 桥接、安装器与真实 100%/125%/150% DPI 仍需 Windows 构建宿主和设备验证。
2. 两台 Android 主观验收通过；低端连续画面约 59.5–60 FPS，有少量超预算帧。高端系统可能调度到 60Hz，应用请求最高刷新率不等于系统保证全程 120 FPS。
3. 低性能判定为硬件启发式，不能识别所有 GPU/温控组合。长时间运行、电池功耗和桌面自动刷新模式没有补充实测。
4. 本轮正式配置包不包含帧诊断，不等于已完成正式签名、公证、远端门禁和公开下载核验。本机 macOS 最终连接态操作此前被自动审批拒绝，尚未新增该连接态证据。

### Windows 更新弹窗测试的时序修订

首次完整 `make verify` 在最后 Windows 阶段出现 3 项更新弹窗失败：首个真实文件发布流程未在 30 秒测试等待内到达完成提示，随后两项也未到达预期界面；结合全局下载互斥机制，推断存在首项失败后的连带影响。单独执行原测试文件时 18 项通过、1 项平台跳过；首个弹窗流程约 26 秒，贴近原上限。将该测试辅助函数的等待上限改为 60 秒，保留完整下载、SHA-256、文件归属与提示文案断言。没有修改客户端更新逻辑或实际网络超时。

此项作为测试对本机执行时序敏感的维护问题记录；单独通过不替代完整 Windows 重跑，后续结果见最终记录。
