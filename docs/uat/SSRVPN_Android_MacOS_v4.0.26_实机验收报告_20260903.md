# SSRVPN v4.0.26 Android / macOS 实机验收报告

## 1. 结论

2026-09-03 已在一台 USB 调试 Android 手机和发布操作所在的 macOS 本机完成
`v4.0.26+4026` 正式包增量验收。两端连接、真实数据通道、模式切换、国内应用旁路、
浏览器与海外应用继续进入 TUN、远程规则复用、断开恢复均未发现阻断用户使用的问题。

本轮发现一个不阻断连接的问题：Android 在 Wi-Fi、移动数据均关闭并开启飞行模式后，
手动重新运行诊断仍把“节点与外部网络”显示为通过；主页同时能够正确显示“网络待确认”。
该问题已记录为 [#193](https://github.com/Elegying/SSRVPN/issues/193)，按维护者要求在下一
客户端版本连带修复，不修改或重发 `v4.0.26`。

macOS 两次 TUN 连接从用户点击到应用就绪的日志耗时分别约 `13.6s` 和 `14.0s`，其中包含
等待用户输入管理员密码的时间。本报告只保留原始观察，不将其认定为启动性能缺陷，也不据此
安排修复。若以后需要优化，应先把人工授权等待与程序执行阶段分开计时。

| 场景 | 结果 | 证据摘要 |
| --- | --- | --- |
| 安装与连接 | 通过 | 正式版正常运行；智能模式连接后系统 VPN 为 `CONNECTED/VALIDATED`，`tun0` 存在 |
| 运行日志入口 | 通过 | 订阅页右上角显示带文字的“运行日志”按钮，能够打开规整诊断页 |
| 智能模式国内应用旁路 | 通过 | 抖音、微信、QQ、淘宝、京东、哔哩哔哩、微博、快手、拼多多 UID 均不进入 TUN |
| 浏览器与海外应用保护 | 通过 | Telegram、Android Browser、夸克浏览器 UID 继续进入 TUN，没有被国内名单误排除 |
| 全局模式 | 通过 | 切换全局后上述 UID 均进入 TUN；切回智能后国内应用旁路恢复 |
| 抖音数据路径 | 通过（增量） | 视频页可用，两个不同评论面板均能加载评论和内嵌图片；消息列表和一个私信会话中的图片/表情可加载 |
| 国内应用 | 通过（启动级） | 淘宝、哔哩哔哩、微信能够启动；本轮未把启动级检查冒充完整业务矩阵 |
| 海外应用 | 通过 | Google 与 Telegram 可加载实际在线内容 |
| 连续重连 | 通过 | 五轮连接均成功，应用记录的连接耗时为 `463/474/442/469/553ms` |
| 真实断网与恢复 | 连接恢复通过 | Wi-Fi、移动数据关闭并开启飞行模式后 HTTPS 与 DNS 请求失败，应用显示“网络待确认”，VPN 进程和 TUN 保持；恢复 Wi-Fi 后约 `3972ms` 再次取得 Google HTTPS 200 |
| 断网诊断 | 发现问题 | 完全断网时手动重跑诊断，“节点与外部网络”仍显示通过；见 [#193](https://github.com/Elegying/SSRVPN/issues/193) |

抖音验收只执行了两个不同评论面板和一个私信会话，没有发送消息、点赞或关注，也没有达到
正式矩阵中“连续 20 轮”的长期样本，因此结论限定为本次增量场景通过。

断网测试后已关闭飞行模式、恢复 Wi-Fi，移动数据保持测试前的关闭状态；SSRVPN 回到智能
模式并保持连接，系统网络重新处于 `CONNECTED/VALIDATED`。

## 5. 远程规则实机结果

- macOS 首次连接约两分钟后把旧/未知状态更新为规则版本 `1.1.0`，六份 provider 均可用。
- 随后重新连接并等待约两分钟，日志明确记录“智能规则已是最新版本 1.1.0，无需下载”；六份
  provider 本地文件修改时间保持不变，证明同版本检查没有重复下载规则正文。
- Android 诊断显示当前有效规则版本为 `1.1.0`；本轮没有单独取得 Android 连接满两分钟后的
  版本请求与文件时间证据，因此不将其标记为 Android 同版本零下载实机通过。
- 本轮没有注入损坏清单、错误摘要或部分 provider 热更新失败；这些失败安全边界继续由现有
  自动化覆盖，不冒充实机故障注入通过。

## 6. 后续事项

下一客户端版本处理 [#193](https://github.com/Elegying/SSRVPN/issues/193) 时，至少应满足：

1. Android 真实完全断网后重新诊断，“节点与外部网络”不能显示通过，应显示提醒或失败。
2. 网络恢复后重新诊断能够恢复为通过，不留下永久错误状态。
3. 诊断不得为了判断外网状态阻塞连接、停止 TUN、修改路由或绕过当前代理。
4. 探测超时、DNS 异常或结果不确定时使用“待确认”等诚实状态，不能把未知结果冒充通过。
5. 增加自动回归，并再次在 Android 真机执行断网与恢复验收。

macOS 本轮观察到的约 14 秒端到端时间不进入缺陷清单；除非后续排除人工授权等待后仍有明确、
可复现的程序阶段瓶颈，否则不为追求表面耗时修改稳定的 TUN 启动与授权流程。
