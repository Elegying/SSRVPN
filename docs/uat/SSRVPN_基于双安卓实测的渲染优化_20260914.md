# 基于两台安卓实测的渲染优化

2026-09-14。按用户要求取消第三台 evergo 的测试；该机安装、输入权限及 USB 中断导致的样本均无效，不用于结论。本轮只参考此前 Android 17 高配手机与 Redmi Note 8 的有效数据。

## 数据指向

- 高配手机首页 CPU 平均约单核 56.4%，GPU 活跃时间占墙钟约 71.5%；后台 CPU 0.1%、GPU 活跃比例约 1%。前台持续渲染有明显成本。
- Redmi Note 8 已命中既有 minimal 低配模式，**此模式没有原生背景模糊和自定义玻璃 Shader**。其滚动 raster P95 仍约 18.24–19.38 ms，超 16.67 ms 帧预算比例约 13.8%。不能将该结果简单归因于玻璃模糊，需同时减少背景与前景的重复绘制。
- 两台的画质分档不同，CPU 百分比不能直接作为同画质优化对照；以上均是本轮修改前数据。

## 实际修改

### 将背景压暗合并到图片绘制

原背景每帧先绘制图片，再绘制覆盖全屏的黑色半透明矩形。改为 Image 的 color + BlendMode.srcATop，使同样的黑色混合在图片 Paint 上完成，移除正常显示时额外的全屏覆盖层。Flutter 3.44.1 本地 paintImage 实现将 colorFilter 直接赋给 Paint；本次未使用会单独建立图层的 ColorFiltered 包装。

对不透明的 RGB 背景，两种操作均为 `输出 RGB = 原 RGB × (1 - 黑色透明度)`。保留普通 .28、高对比度 .65、原图、BoxFit.cover、medium 过滤、裁切、运动轨迹与频率。加载和失败占位仍保留压暗。

在 1080×2340 和 1200×2608、60 Hz 下，被移除的全屏矩形每秒覆盖约 1.52 亿和 1.88 亿像素位置。这是减少的覆盖量，**不是测得的 GPU 性能提升比例**；具体收益取决于渲染后端是否已经合并指令、颜色过滤实现及设备带宽。

### 流量数值未变时不重建卡片

采样继续按原节奏执行，且始终更新上一次采样基线。仅当上传速率、下载速率、累计量或可用状态变化时 setState；重复失败只显示一次相同错误状态。这样避免连接空闲时重建卡片和重新布局文字，也不把长时间空闲算进下一次瞬时速率。

这项改动主要针对连接空闲状态，**不是此前未连接首页高负载的唯一修复**。

## 验证与边界

- 使用真实背景 PNG，对旧结构与当前生产 SsrvpnAppBackdrop 做像素对照：竖屏、横屏及普通/高对比度模式，8 位颜色通道差异最多 1；无额外 ColorFiltered 图层组件。
- 玻璃捕获的静止纹理复用、背景晚到更新、页面移动、尺寸变化、后台恢复、销毁和表单状态回归保持通过。
- 新流量测试覆盖无变化时保留卡片、采样基线持续推进、失败不重复重建、恢复时正确更新。现有速率回归、跨连接代际、尺寸与大字体测试继续执行。
- 没有降低显示分辨率、模糊参数、透明度或动画帧率；未扩大 minimal 设备范围；未引入新的全屏纹理缓存。
- 用户已取消第三台测试，本轮不再操作该机做性能采样。尚无两台原设备的修改后 A/B 数据，因此不能宣布卡顿已彻底修复，也不能给出 CPU/GPU 改善百分比。
- 先前 artifacts/device-audit-20260914 中的 APK/ZIP 是优化前基线包，不包含本轮新增修改。本轮未构建新安装包、未提交、推送或发布。
