**N03：安装目录的文件归属过宽，尚未修复。** 最小触发是正常 SSRVPN 安装目录中额外放入
`unrelated.txt` 或自己的子目录，再执行覆盖升级；无需选择特殊路径。基线
`SSRVPN_Windows/installer/SSRVPN.iss:618–638` 依次调用 Recover、Begin、Clear；
`program_files_transaction.ps1:454–462,534–540` 将除 `bin\\ssrvpn` 以外的文件都纳入程序库存，
`:1129–1170` 递归清除这些条目，`:1439–1458` 在安装验证成功后提交并清除备份。
路径、reparse point、数量、哈希和回滚检查约束了安全遍历与失败恢复，不能证明文件属于应用。
`SSRVPN.iss:69–73` 的 `[InstallDelete]` 另有 `{app}\\*` 等宽泛清理，也必须同时收窄。
新 payload 清单仅验证新安装内容，不能赋予旧无关文件删除归属。

已核对产品硬规则 9 和覆盖安装提示的“只清理已知程序文件”；ADR-002 的数据保留、ADR-020
代理恢复、ADR-021 同名进程政策均未授权清除任意文件。Inno 的 Browse 默认追加应用子目录
不能排除上述正常安装目录用例，因此不夸大为“点击桌面就会清空桌面”。当前安装器未改；本机
没有 Windows/PowerShell 5.1/Inno 行为环境，无法可靠验证涉及数据删除及失败回滚的补丁，
37 项源码静态检查通过不构成反证。潜在用户损失明确，实际触发概率未知。

第二轮补充同根因证据：Recover `:1387` 重新按全目录删除，Begin 后新增的无关文件甚至不在
旧备份中；旧目录 A 卸载调用 Discard（`.iss:883–889`），helper `:1462–1475` 不核对 state
就删除共享恢复根，可能清掉另一目录 B 失败安装留下的恢复材料。正常 Recover `:961–999`
有 installDir/metadata 身份检查，不能将这个 Discard 缺口泛化为任意跨目录恢复均无保护。

具体待实施方案：可信新旧程序清单约束 Clear/Recover/Commit、Discard 和 `[InstallDelete]`；
未知文件、第三方改写和其他目录事务必须保留，冲突时在破坏操作前停止。现有新包清单没有
持久化为旧程序归属，Begin 的全目录快照也不是归属证明。旧版迁移需随包提供经验证的受支持
旧版本程序清单，或提供保留数据的空目录迁移，不能仅用新清单漏掉旧 DLL，也不能静默放宽
现有完整性校验。先在隔离 Windows 加根目录/子目录哨兵，再覆盖首次安装、升级、各阶段
失败回滚、卸载 A 时 B 有待恢复事务、旧版迁移；核对数据目录和合法程序替换。见 [路线图](ROADMAP.md)。

**N04：卸载注册表的恢复范围与管理员安装不一致，尚未修复。** 基线 `.iss:42,46` 固定
管理员及 x64 安装，卸载项归 HKLM；`program_files_transaction.ps1:634–811` 的快照、
验证、删除和恢复却均固定 HKCU，state `:961–999` 也没有 hive/view。
Inno 先写卸载信息并提交自身日志，再调用项目 `ssPostInstall`。如果 helper 启动或 committed
标志落盘前暂时失败，prepared 保留，最终退出的 `DeinitializeSetup`（`.iss:845–855`）尝试
自有恢复；恢复材料有效且恢复成功时，旧程序回来，HKLM 仍可能记录新版本/路径。
首次或改目录安装也可能留下指向已清除卸载器的记录。触发概率未知，未证明订阅丢失。
依据为 [官方安装模式](https://jrsoftware.org/ishelp/topic_admininstallmode.htm)、
[安装顺序](https://jrsoftware.org/ishelp/topic_installorder.htm) 及
[Inno 6.5.0 引擎实现](https://github.com/jrsoftware/issrc/blob/is-6_5_0/Projects/Src/Setup.Install.pas#L3508)。

已反证：committed 写入后的清理失败返回成功或让 Recover 仅清残留，不属于此触发；单独
status 写失败也不决定安装失败。ssPostInstall 异常会被引擎捕获，不代表立即自动回滚；
恢复材料无效或持续写失败时，也不能声称旧文件已经恢复。现有测试分别证明 HKCU 自有恢复和
HKLM 正常安装，未覆盖真实安装末段的交叉故障。建议在协议中明确、校验并持久化 registry
root/view，贯穿快照和恢复；旧 schema 2 事务缺失 HKLM 旧值，不能猜测或直接换一个常量。
须用隔离 Windows 真实安装器注入 committed 前故障，并核对文件、HKLM64、非目标 HKCU 和
快捷方式，同时保留 committed 后清理失败的反证用例。本机环境不足，安装器未改。

**UI02：更新任务关闭了不属于自己的弹窗。** 基线共享 `update_service.dart:230–240` 和

**SUB02：可提交状态超出下一次操作的恢复预算。** 基线 `subscription_service_persistence.dart:116–123`
不限订阅 metadata 写入大小，但 `subscription_service_transaction.dart:126–150` 拒绝超过
20 MiB 的旧文件进入 undo record。正式 URL 输入没有长度限制，controller `:408–417` 先 add
落盘再刷新，失败保留来源，因此超长/累计 URL 可使正常添加成功后连删除也失败。
两条公开 API 回归覆盖单项 ASCII 和累计 Unicode，修复前均复现；修复按完整 JSON 的 UTF-8
字节预算在写入前拒绝，既有事务保留 metadata/cache/YAML/内存版本，重启与后续删除仍正常。
未扩大 journal 上限、未增加迁移；历史已经超限的文件仍可能无法正常修改，需先备份再显式
恢复，不能宣称这类历史数据也已修好。本轮未读取用户真实订阅，也不声称普通订阅高频触发。

**MAC01：同一应用 PID 的旧 TUN 状态被快速重试接受。** 基线 session `:280,321–333,703–760`
按“本次时间减一秒”判断状态文件新鲜度，runner `:12–15,158,659–724` 只写状态词且会保留错误。
失败后在该窗口内重试，新授权尚未写状态时就可能读取旧 error，让新 start 提前返回 false。
受控服务测试证明这一误判；实际 coordinator 随后会 cancelIntent/interruptPendingStart，
所以不把底层测试中暂时保留的 handle 夸大为长期孤儿进程或持续断网。旧 running 的拒收作为
补充防线，不另称已复现生产假连接。
修复复用既有 request nonce，将 active runner 的状态词绑定本次请求，所有相关读取同时核对
归属；保留文件时间、类型、64 字节上限与取消代次保护。recovery-only 保留原状态格式，
同步更新固定 runner SHA-256。回归覆盖旧 nonce 晚写、本轮 starting/running/error、授权早退、
取消和 DNS 恢复 handoff；实际状态写函数只在临时目录执行。真实授权/特权进程仍待目标环境验收。

**N01：旧 Android 监控收尾。** 基线 `SsrvpnVpnService.kt:691–720` 在监控返回后直接恢复，
异常分支直接 `stopAll`。线程可在最后一次循环代次校验后暂停，待断开和下一次连接完成才继续。
新连接已清除手动停止标记，`reserveRecovery` 只确认当前有运行连接，因此既有循环检查、
恢复上限和停止合并均不能排除误归属。修复复用 `StartGenerationGate.runIfCurrent`，在既有
[CoreLivenessMonitor](../SSRVPN_Android/android/app/src/main/kotlin/com/ssrvpn/android/CoreLivenessMonitor.kt)
中统一结果与异常的原子分发；探针和等待保持在锁外。回归先等价提取旧分发逻辑，再证明
新连接被旧回调停止，补门禁后新连接/配置保持、恢复与失败通知为零；当前会话行为仍通过。
这不是声称新辅助函数测试直接运行在完全未改动的提交上。风险是锁内副作用顺序，已复核
可重入和锁顺序，未改恢复预算及 TUN 清理策略。

**SUB01：格式识别和合并语义不一致。** 基线 `subscription_yaml_merger.dart:72–86,302–330`
按文本行截取节点；`subscription_service_base.dart:376–401` 调用 normalize，而

回归风险是完整 YAML 语义与别名展开；20 MB 展开预算不是进程 RSS 上限，也未据此声称性能改善。

**CONN01：异步 guard 晚到。** 基线 `clash_service_base.dart:431–435` 在等待外部会话检查前

不会把伪服务器晚处理已发请求当成客户端在新会话创建旧请求的证据。

**N02：运行中原生会话替换。** 基线 Android bridge `379–381,438–440` 已计算 sessionChanged，
