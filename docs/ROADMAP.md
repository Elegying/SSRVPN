# 路线图

路线图只保留能提高用户结果且有明确验收证据的工作。已完成内容进入 `CHANGELOG.md`，不在这里重复堆积。

统一诊断与恢复、读屏语义和键盘测试、关键路径性能基线、订阅/诊断/私有存储职责拆分、
Android 应用模块内置 Kotlin、Windows 中文无提权安装与核心单次恢复已完成并进入
`make verify`。桌面固定走免费分发；系统不会验证受信任发布者，文档和 UI 必须持续如实提示。

### 1. 下一版本三端与 Android 体验修复

以下问题由真机 UAT 与产品复核确认，作为下一版本的优先修复项：

| ID | 平台 | 问题 | 期望修复 |
| --- | --- | --- | --- |
| CROSS-NEXT-01 | Android、Windows、macOS | 订阅刷新成功或失败的结果提示会一直保留 | 每次刷新结果显示后 10 秒自动消失；新结果替换旧结果并重新计时，页面销毁时取消待执行计时器 |
| CROSS-NEXT-02 | Android、Windows、macOS | 选择“全局”后，代理模式副标题仍可能显示“国内直连，国外走代理” | 三端副标题都必须随模式更新：智能显示“国内直连，国外走代理”，全局显示“所有流量均走代理” |
| ANDROID-NEXT-01 | Android | 点击添加订阅输入框时，系统弹出安全键盘 | 输入框使用用户配置的默认键盘，不再声明为密码或安全键盘输入；订阅 URL 的日志、诊断和存储脱敏边界保持不变 |
| ANDROID-NEXT-02 | Android | 长按添加订阅输入框时，编辑菜单显示英文 `Paste` | 中文系统与中文应用环境下显示“粘贴”，并保持实际粘贴功能可用 |
| ANDROID-NEXT-03 | Android | 已连接时从“全局”切回“智能”会停止 VPN 核心但不自动重连，客户端可能在节点页静默变为未连接 | 模式与节点热切换必须保留用户的连接意图，并在同一串行事务内完成旧核心停止、新配置启动与健康确认；失败时恢复原连接或明确提示已断开，客户端状态、系统 VPN 与实际数据通道必须一致 |

完成标准：三端订阅刷新成功与失败结果都必须立即显示，在第 9 秒仍可见、满 10 秒后消失；连续
刷新只允许最新结果及其计时器生效。为结果生命周期和模式说明补充可控时钟的 Widget 回归，
并在 Android、Windows 与 macOS 各完成一次界面验证。在中文 Android 17 / HyperOS 真机上
以系统默认输入法分别验证 100% 与 200% 字体，确认聚焦输入框不会切换安全键盘，长按菜单只
显示“粘贴”而不是 `Paste`，粘贴订阅后仍可正常添加。对应发布回归必须执行
[C-11、C-12](UAT_MATRIX.md#所有平台共同流程) 与 [A-07、A-08](UAT_MATRIX.md#android)。Android
连接态回归还必须在真机上连续执行至少 5 轮 `智能 → 全局 → 智能`，并交替执行模式与节点
切换；每一步都确认应用连接状态、系统 VPN Service 和真实 HTTPS 数据通道一致。对新核心启动
失败进行故障注入时，不得静默断开，必须恢复旧连接或给出明确且可操作的失败提示。

### 2. 真机无障碍与生命周期矩阵

- 用 TalkBack、VoiceOver 和 Narrator 走完首次导入、节点选择、连接/取消、错误重试和断开。
- Android 真机验证首次授权、后台重启、快捷磁贴、通知断开、休眠/唤醒和弱网取消。
- macOS 验证系统代理和 TUN 的授权取消、连接、异常退出、Dock 重开与网络设置恢复。

完成标准：关键流程有平台与系统版本、读屏器、步骤、结果和截图/日志证据；现有 Widget
语义测试继续作为回归门禁，但不冒充真机验收。

### 3. 按变更风险执行 Windows 发布烟雾测试

现有 Windows 11 UAT 作为当前基线，不再为不触达 Windows 的改动重复完整矩阵。后续修改
安装器、代理恢复、guardian、TUN 或内置更新，或准备新的正式版本时，再在安装版完成对应
首次启动、覆盖升级、连接/断开、数据保留和卸载烟雾测试。

完成标准：记录版本、提交、系统版本、安装包哈希、触达边界和结果；发现的问题先进入自动
回归，再修改高风险实现。

## 后续改进

### 可维护性

- 继续提高 Windows `clash_service_lifecycle.dart` 的行为覆盖率；当前渐进门槛为 25%，新增启动、提交、回滚或停止分支时同步提高证据和门槛。
- 已完成共享更新 façade、macOS 原生核心/应用支持和 Windows 代理模型的第一轮低风险职责拆分；后续继续遵守 [ADR-010](decisions/010-risk-controlled-maintainability-boundaries.md)，只处理有新增行为证据的切片。
- Android VPN Service 与 Windows 安装回滚继续作为受规模护栏保护的热点；只有目标平台故障注入能先证明取消、所有权和恢复不变量时，才进行下一轮跨对象拆分。
- 保持共享领域逻辑单一来源，平台层只承载 OS 集成与差异文案。
- 第三方 Flutter 插件完成 AGP 9 迁移后，删除 Android 全局 `builtInKotlin=false` 与旧 KGP
  兼容声明；应用模块本身不得回退旧插件。

完成标准：每个切片减少职责或重复，并保持 `make verify` 与目标平台构建通过；不接受只有行数变化的重构，也不把结构门禁冒充目标平台运行证据。

### 可观测性与性能

- 在低端 Android 与目标桌面机重复现有订阅解析、合并、配置生成基线，再补充启动、连接
  和取消的非敏感阶段耗时。
- 诊断报告继续保持默认脱敏、有大小上限并由用户主动复制；只有明确用户需求时再增加
  文件导出，不默认收集或上传。

完成标准：基线脚本、样本条件和前后数据可复现，优化不牺牲取消与回滚语义。

## 不作为当前目标

- 不购买 Apple Developer ID 或 Windows Authenticode 证书，不恢复付费桌面签名自动化。
- 不在没有稳定 macOS 代码身份时把 `.api-secret` 迁入依赖代码身份 ACL 的 Keychain。
- 不为追求目录一致而强行共享三端 UI。
- 不在没有证据时替换 Mihomo、状态管理方案或发布系统。
- 不为“告警归零”提前删除 Flutter 当前仍需要的 Gradle/Kotlin 兼容开关；必须等待上游插件与工具链支持并用 APK/原生测试证明迁移。
- 不用排除源码、无断言测试或大量模板文档制造“评分提升”。
- 不恢复 setuid 核心，也不把 macOS TUN 提权变成持久 root 安装。

当前评分与风险依据见 [项目健康状态](PROJECT_HEALTH.md)。
