# SSRVPN 项目硬性规则

本清单是当前开发、审查、测试和发布的强制约束。规则来自已接受的 ADR、用户明确决策、
安全策略和现有回归门禁，不是建议项。任何改动若需要突破本清单，必须先取得维护者明确确认，
更新对应 ADR、测试、用户文档和回滚方案后才能实施。

## 1. 产品范围与平台

1. Android、macOS 和 Windows 的主导航包含“首页/主页”“订阅”和“设置”三项；不得恢复隐藏的解锁测试、后台检测服务或替代性实验入口。
2. 三端保持同一核心流程：导入订阅或节点、选择节点、建立连接、查看状态、断开连接；平台差异只用于操作系统集成。
3. Android 正式包最低支持 Android 7.0，仅发布 `arm64-v8a` APK，并必须保持同一正式自签名证书谱系。
4. macOS 正式包最低支持 macOS 11，仅支持 Apple M 系列 `arm64`；不得宣称支持 Intel 或 `x86_64`。
5. Windows 最低支持 Windows 10 1507（build 10240）x64，只发布每用户安装器 `SSRVPN_Setup.exe`，不得恢复便携 ZIP 发布链。Windows 客户端及外层启动器必须继续声明 `requireAdministrator`，整套客户端固定以管理员身份运行；不得在未取得维护者明确确认时改成仅 TUN 提权、拆分权限或普通权限运行。
6. macOS 固定采用 ad-hoc、未公证免费分发；Windows 固定采用未签名安装器。除非维护者明确取代该决策，不引入 Apple Developer ID、公证、Authenticode、付费证书 secret 或对应自动化。

## 2. 安装、升级与用户数据

7. macOS DMG 根目录必须包含 `SSRVPN.app` 和指向 `/Applications` 的快捷方式，支持拖拽安装。
8. Windows 固定安装到 `%LOCALAPPDATA%\Programs\SSRVPN`，不提供安装目录选择；安装阶段可以请求管理员权限，但不得因此改装到 Program Files。
9. Windows 覆盖升级、卸载和保留数据后的重装必须保留安装版订阅、设置、DPAPI 密钥、LocalAppData 回退数据和窗口状态，只替换已知程序文件。
10. Windows 安装器不得搜索、迁移、合并、修改或删除桌面、下载目录及其他位置的旧独立副本；存在其他运行中副本时，应在改动系统代理前停止安装并提示用户自行退出。
11. 安装、卸载、退出和异常恢复只可结束路径、PID、会话、创建时间和所有权能够证明属于当前 SSRVPN 安装的进程；不得按 Clash、OpenVPN、WireGuard、Tailscale、ZeroTier 等通用名称结束第三方软件。
12. 安装或升级事务不明确时必须失败关闭并保留用户数据、安装包和恢复证据，不得用猜测性清理换取继续安装。

## 3. 订阅与节点数据

订阅只提供节点及其连接参数，不提供客户端策略。导入、刷新和多订阅合并只提取 `proxies`；上游的规则、规则来源、代理组、远程节点来源、DNS、hosts、脚本、监听器、TUN 和运行模式等配置均不得进入客户端运行配置。旧缓存即使含有这些字段，也必须在生成运行配置时隔离。客户端自行生成分流策略，上游内容不得覆盖用户手动强制代理或强制直连。仅含远程节点来源而没有实际节点的订阅，不自动展开其远程配置。

13. 首次打开或没有节点时，应用必须引导用户导入订阅链接或节点链接；引导与订阅页共用控制器，新订阅和重试只拉取指定来源，本地节点直接校验并保存，成功后加载节点并开始测速。无效本地节点不得因为已有其他可用节点而被报告为导入成功。
14. 订阅输入、重定向、DNS 解析、响应头、响应体、编码、节点数量和解析深度必须有界；HTTPS 重定向不得降级到 HTTP，证书校验不得被生产代码绕过。允许用户主动填写内网 IP 订阅，但重定向不得将请求转向不同的非公网 IP 或端口；同一明确指定的内网 IP 与端口内可相对跳转。
15. 为兼容现有服务，订阅入口继续接受合法 HTTP 与 HTTPS 地址；界面和用户指南必须推荐 HTTPS，不得把 HTTP 描述为具有传输保密性。
16. 刷新或导入失败不得破坏失败来源最后一份可用节点。多订阅刷新部分失败时提交成功来源、保留失败来源缓存，并明确区分成功和失败；本地节点导入和订阅删除不得依赖其他远程来源联网成功。
17. 订阅改名只更新显示元数据，不触发重连或重置测速；链接编辑只刷新该来源，不覆盖其他来源的手工编辑，并保留启用与自动更新设置。新链接获取有效节点后更新成功时间，失败则保留旧链接和节点。
18. 订阅、节点、设置和 secret 的写入必须采用平台已有的串行化、原子替换和失败保留边界，不得先删除唯一可用旧数据再尝试写入新数据。订阅 JSON 与节点 YAML 必须由同一恢复记录保护，未提交的写入在重启时恢复；旧缓存不能证明节点独占归属时，保留历史节点直到剩余来源全部成功刷新。

## 4. 节点选择与延迟

19. 节点延迟统一只测节点服务器与端口的 TCP 连接建立时间（包含必要的 DNS 解析）；生产实现必须使用原生接口将 DNS 与 TCP 绑定到同一个非 VPN 物理网络，绕过 TUN 接管与假 IP 缓存。不能确认物理路径、绑定失败或超时时必须返回失败，不得回退到未绑定的 Socket。不得改为经 Mihomo、代理 HTTP、目标网站状态码或完整协议握手测速。**展示层例外（既定产品策略，不得移除）**：名称包含「私家车」且探测未超时、未失败时，节点延迟的展示值替换为 24–39 ms 的随机数，该展示值参与延迟升序排序与颜色分级；探测方法本身不变，超时与失败值原样展示。
20. 测速必须有超时、取消、并发上限和结果代际；旧测速结果不得覆盖刷新、删除或重新导入后的新节点状态。
21. 测速超时节点必须置底、变灰并保留检查或编辑入口；未连接时仍允许预选可运行节点。**延迟只用于排序与默认节点取值参考，不作为手动选择的闸门**：已连接状态下，超时、失败或未测速的**可运行**节点同样允许手动切换——用户显式点击优先于测速结果。该行为由 `home_node_controller_test.dart` 的「latency only sorts nodes and never blocks manual selection」与 `home_latency_controller_test.dart` 的「canSelect ignores failed or unknown latency for runnable nodes」两个用例锁定，改动需同步。
22. 节点默认保持订阅原始顺序；只有用户主动点击排序按钮时，当前页面才按延迟升序显示，再次点击恢复默认顺序。排序不得写回订阅、节点配置或记忆节点。
23. 应用必须记忆最近一次选择的节点；Android 快捷磁贴连接沿用该节点，不得因为尚未测速或一次测速超时静默改选其他节点。

国旗补充要求（2026-09-08）：名称、emoji 与地区元数据只作初始提示；稳定连接 15 秒后才在后台
观察当前节点最终代理出口 IP，使用已有本地 GeoIP 数据库更新国别，不能以中转服务器入口地址
或 DNS 解析结果代替出口。查询前后均核对核心实际选中节点，不向其他未连接节点套用当前出口。
查询不得加入测速链、切换当前节点或阻塞连接；测速、切换与断开时取消请求。出口探测域名必须
通过代理，避免用户直连规则污染结果。按协议、地址、端口、凭据及线路参数摘要持久缓存成功国别，
链式代理依赖变化时失效；未变化线路复用，改名不重新查询。升级时废弃旧入口 IP 国别缓存。
失败保留原显示，未知仍显示地球；未连接节点沿用已有缓存或名称提示。缓存不得保存明文节点、
出口 IP、凭据或订阅信息。

## 5. 建连、健康与恢复

24. 只有核心进程、受认证本地 API 和目标平台的 VPN、系统代理或 TUN 均确认就绪后，界面才可显示“已连接”；端口开放或启动命令返回不能单独作为成功依据。
25. 建链必需条件、本地核心存活和连接后的外部可达性必须分层。外部站点暂时不可达只能产生建议性提示，不得据此自动断开、重启核心或切换节点。macOS TUN 授权取消或超时必须返回可重试状态，不得自动降级到用户未选择的模式。
26. “连接中”必须允许取消。取消、重复点击、旧代际回调、迟到权限结果或旧健康探针不得覆盖更新一代连接状态。
27. Android 核心意外退出最多执行两次受控恢复；恢复中和最终失败必须明确通知，用户主动断开不得触发自动重连。
28. macOS 和 Windows 的系统代理只在仍由 SSRVPN 持有相同端点时恢复；用户或其他软件后续修改的代理设置不得被覆盖。
29. 端口冲突自动改用临时 mixed、SOCKS 或 API 端口时必须向用户列出实际变化；下一次未调整时不得继续显示旧提示。
30. 三端对未连接、正在连接、已连接、已连接（有提醒）、正在断开和连接异常的语义必须一致；错误提示应使用稳定分类和可执行建议，不直接显示原始异常或敏感值。

## 6. 路由与网络

31. 三端只提供“智能”和“全局”，核心均序列化为 `rule` 以保留应用和手动规则。Android 国内应用先由系统 VPN 排除；进入内核的流量先执行 Android 国外应用代理、用户强制代理、用户强制直连。智能模式随后依次执行公网 IP 探测域名代理、私网安全、自动海外代理、GFW 代理、国内企业域名与 ASN 直连、国内域名/IP 直连，最终 `MATCH,PROXY`；全局模式在应用和手动规则后执行 `MATCH,GLOBAL`。两种模式都保留 Android 应用名单。
32. 未命中 Android 应用名单的流量，用户手动规则高于自动目标规则。同一主机的 URL、大小写、末尾点等不同写法归为同一目标，后保存的一侧移除另一侧；父域和子域重叠时仍以强制代理优先。代理域名使用代理 DNS，强制直连和国内域名使用国内 DNS；强制 IP 地址只生成 IP 路由规则（IPv4 用 `IP-CIDR`，IPv6 用 `IP-CIDR6`）。输入界面允许完整输入 IPv6 地址并保留保存时的格式校验。域名判断先于 IP 判断。
33. 三端运行配置启用双栈：核心与 DNS 均开启 IPv6，生成 IPv4 / IPv6 两套 Fake-IP 池，TUN 接管 IPv4 / IPv6 并沿用同一套分流规则；首页公网 IP 仍只展示 IPv4。详见 ADR-018。
34. Android 与 Windows TUN 接管进入隧道的 IPv6 并按同一套规则分流，不排除 IPv6 路由；Android 系统排除应用使用系统网络，不受内核策略控制。三端均不修改操作系统全局 IPv6 开关。
35. 规则通道独立于源码仓库，公开发布签名快照。每次 App 启动后的首次成功连接等待两分钟检查一次，计时期间断线取消，重连后重新等待；实际发起检查后本次运行不重试，不因切节点、重连或回到前台重复检查。三份数据（公共规则、安卓直连应用、安卓代理应用）独立版本，由统一索引绑定；桌面端不下载应用名单。先验证索引签名，版本较新才获取固定快照清单，只下载摘要变化的文件，完整校验后原子提交；静默失败保留旧数据，不热更新或自动重连，下次连接启用。随包携带完整基线，未知公网流量代理；上游固定版本每日同步并验证，异常数据不发布。详见 ADR-017。
36. Android 应用名单优先于用户手动规则：国内应用通过系统 VPN 排除直接联网，国外应用在内核中强制代理；两种代理模式均遵循此优先级。未命中名单的流量按用户手动规则、公共目标规则、未知公网代理处理，全局模式未命中名单和手动规则的流量交给 GLOBAL。通用浏览器不得加入名单，运行时也排除浏览器匹配；包名无法识别、共享 UID 或系统查询不支持时按访问目标分流。应用名单使用精确包名且互斥。国内排除名单随受保护连接配置保存，磁贴启动与进程恢复使用相同版本；更新下次连接生效。不得上传设备应用清单。

## 7. 更新与发布来源

37. 三端自动检查更新只有在节点连接成功或恢复连接态得到确认后才能发起；未连接启动、首页初始化或未知恢复状态不得自动请求。用户可在“关于”中主动检查更新，失败只提示重试，不得影响连接、启动或现有版本使用。
38. 应用内更新只接受 `Elegying/SSRVPN` 正式 GitHub Release 的规范平台资产及同名 SHA-256；元数据、资产名、tag、下载 URL 或摘要不匹配时失败关闭，不得回退 OSS。
39. 发现新版时只在底部版本号旁持续显示“发现新版本 立即更新”；未经用户点击不得自动打开更新页、自动安装或强制退出。
40. 下载必须显示进度并允许取消；只有完成 SHA-256 校验的文件才可发布到目标位置或交给系统安装，失败和取消不得损坏已有目标。
41. Windows 只可清理由 v4.0.15 或更高客户端内置更新器下载、校验、写入专属标记且安装事务成功的版本化安装包。旧客户端、手动下载、取消、失败、身份不匹配、非普通文件和同目录其他文件必须保留。标记遗留后的同版本重下必须使用由规范文件名和可信 SHA-256 派生的独立备用名，不得认领或覆盖旧标记；中断恢复候选只读且必须保留原文件。
42. OSS 只作为网站、人工分发、不可变归档和发布事务镜像；不得重新成为客户端更新权威或静默备用源。

## 8. 安全、隐私与诊断

43. `apiSecret` 不得写回普通设置 JSON。Android 使用安全存储，Windows 使用当前用户 DPAPI，macOS 使用权限为 `0600` 的独立文件，并按各平台既有迁移和失败回滚边界处理。
44. 日志、错误、剪贴板诊断和崩溃报告必须限长并经过共享脱敏；订阅 URL、Token、密码、Authorization、用户目录和公网地址不得原样进入可分享内容。
45. SSRVPN 不内置遥测，不自动上传日志、崩溃报告、订阅或节点数据；诊断由用户主动查看、复制并在分享前复核。
46. macOS TUN 管理员授权按次生效，SSRVPN 不读取或保存系统密码；临时 root runner 必须绑定当前应用会话并在断开、退出或失败时清理。
47. 动态状态不得只靠颜色表达；关键按钮、错误、进度和对话框必须具备可读语义、合理焦点顺序，并支持窄窗和大字号滚动关闭。三端“运行日志”必须在订阅页右上角以可见文字呈现，窄窗和大字号不得只剩无说明图标，节点选择页不得保留重复入口。诊断默认内容必须用中文结论、检查结果和本地时间运行记录解释问题，内部事件名、会话编号、路径及冗余核心信息只可放在默认收起的脱敏技术明细中。节点页订阅筛选和延迟排序必须保持为两个独立点击区域；订阅选择、“关于”和“使用教程”继续使用统一透明毛玻璃表面。

## 9. 工程、测试与发版

48. `main` 必须保持严格分支保护、线性历史、禁止管理员绕过、禁止 force-push/删除，并维持版本化策略规定的九项必需检查。
49. 正式发版必须绑定精确 `main` 提交、版本号和 CHANGELOG；只有完整门禁通过后才能创建不可变 annotated tag，已推送 tag 不得删除、移动或复用为另一提交。
50. 正式 Release 必须包含 APK、DMG、Windows 安装器、三个 SHA-256 和 provenance；GitHub Release、OSS 不可变目录、固定下载地址和 `latest.json` 必须属于同一事务并可回滚。GeoIP 只能在维护者收到明确更新指令后通过手动维护入口更新；普通 CI、`Prepare Release` 和 `Release` 不检查上游新旧、不自动改写来源记录，也不得因固定快照不是最新版阻断发版。三端仍必须使用同一份固定资产并通过来源与 SHA-256 校验。
51. 自动化测试、平台构建 smoke、人工实机 UAT 和线上公开资产必须分别记录；任何一类证据不得冒充另一类已经执行。
52. 新增或修改用户行为必须增加最小行为回归，并断言用户最终状态、数据保留和系统网络设置；只验证函数返回或进程启动不算验收。
53. 高风险生命周期、安装、代理恢复和 VPN 事务只按有行为证据的职责渐进拆分；不得仅为减少行数改变执行顺序、所有权、回滚或失败关闭边界。

## 规则变更流程

1. 明确记录要改变的规则、用户价值、兼容影响和安全风险。
2. 取得维护者明确确认；重大或昂贵可逆性低的变化新增 ADR，旧 ADR 保留并标记被取代。
3. 先补行为测试和回滚路径，再修改共享实现与平台实现。
4. 同步本清单、[功能列表](FEATURES.zh-CN.md)、用户指南、CHANGELOG、UAT 和发布门禁。
5. 在受影响目标平台完成自动化、构建和必要实机验证后，才可进入正式发布。

53. 设置页三端共用：液态玻璃无/低/中/高、壁纸或七种纯色背景、自定义静态背景图、动态背景开关、代理混合端口、检查更新和运行日志。动态背景三端默认关闭，只有用户显式开启后内置壁纸才缓慢流动；纯色与自定义背景不运行流动动画，开关对其禁用并说明原因。外观保存成功后立即生效，保存失败保留旧值；未选择档位的旧安装继续使用设备默认档位。自定义图片经预览确认后保存到应用目录，最长边限制为 2048 像素；导入失败、取消或原图删除不破坏已保存背景。端口范围 1024–65535，不与 SOCKS/控制端口重复，保存后下次在应用内连接生效。检查更新结果在页内显示，新版本沿用底部更新入口。运行日志复用现有诊断中心。

54. 四档特效由共享材质入口统一控制，兼容容器不得按分辨率绕过用户选择；无/低档不执行玻璃模糊、折射捕获及连接装饰光晕。规则编辑必须保留当前核心的混合、SOCKS、控制端口与 API 身份，直到重连准备阶段重新分配端口。临时避让不覆盖用户保存的端口；下一次连接再次优先尝试用户设置。
