# ADR-017：独立签名规则通道与用户优先分流

日期：2026-09-14。用户已接受，本地实现与开发验证完成；独立规则通道已上线并通过公开下载校验，不代表客户端已发版或实机验收通过。详见 [审查记录](../uat/SSRVPN_独立规则通道审查_20260914.md)。其中“进入内核的流量仍遵循 IPv4-only 边界”一句已被 [ADR-018](018-dual-stack-routing.md) 取代；其余决策（应用名单优先、独立签名通道、更新时机）继续有效。

## 行为

订阅只提供节点。根据用户 2026-09-14 的后续调整，Android 应用名单优先于用户手动规则：国内应用从系统 VPN 排除，国外应用在内核中强制代理。未命中名单时才按手动规则、自动代理/GFW、国内域名/IP、未知代理判断。全局模式同样优先应用名单，再保留手动例外，其他流量交给 GLOBAL。桌面端没有应用名单，仍以手动规则优先。相同手动条目后保存的一侧移除另一侧。进入内核的流量仍遵循 IPv4-only 边界；系统排除应用使用系统网络。通用浏览器按目标分流。

国内名单以受限注释元数据随生成配置保存，原生启动只从受保护配置读取当次名单，避免磁贴启动、进程恢复或规则后台更新混用版本。无元数据的旧配置兼容既有内置名单，显式空名单不回退到旧名单；浏览器不会被系统排除。国内应用绕过内核后，其流量不再受手动域名规则控制。

国外应用通过本地有界管道查询 Android 10+ 连接所属 UID 和包名；使用原始目的地址避免 Fake-IP 转换破坏查询。共享 UID、查询失败、超时、Android 10 以下系统均不猜测应用，按目标分流。包名查询不上传设备数据。精确可见性和启动器/浏览器 intent 查询覆盖常见应用；分身、特殊 OEM、无启动入口应用需实机验收，不能宣称任意包名均可匹配。

## 发布与更新

`Elegying/SSRVPN-Rules` 为独立公开规则仓库；源码仓库可独立设为私有。不得将仓库访问令牌或签名私钥内置客户端。`rule-channel/` 保存发布工具、名单源文件及必要补充规则。公共数据自动从 Loyalsoldier/clash-rules 的固定提交生成；保留来源和许可证。

三份逻辑数据有独立版本，由 manifest 的 componentVersions 记录；公共规则为多个 provider 文件。清单由全局快照版本绑定，version.json 包含其 SHA-256 和 Ed25519 签名。客户端先验证签名，再比较版本，仅从该快照目录下载。桌面端不下载安卓名单。相同内容不提升版本；内容回滚使用更高版本发布，不修改历史快照。

每次进程内服务首次连接后等待两分钟检查一次。等待期间提前断开则取消计时，重连后重新等待两分钟；只有实际发起检查才消耗本次运行的一次机会。只在节点连接可用时请求，更新不发用户通知；失败不重试、不清空规则、不阻断正常连接。完整文件校验通过后原子替换清单作为提交点；当前核心继续使用原版本目录，下次连接使用新版。更新成功不会主动重连。

## 验证与限制

发布端检查格式、大小、数量变化、应用名单互斥、浏览器排除和代表性目标分流；客户端独立验证签名、清单、摘要、大小、条目数和允许语法。拒绝任意内核配置字段及脚本。成熟规则集不能证明每个目标在每个网络实时可达；未被 GFW 收录不等于允许直连。保留离线基线和旧快照，不能以自动化测试替代设备网络验收。

先发布独立规则通道和使用新地址的客户端，再将源码仓库私有；旧客户端不会自动获知新地址。应用安装包更新及核心资产镜像的私有仓库迁移是另外的发布事项。

安卓磁贴冷启动和原生恢复沿用上次受保护连接配置；下载的新快照在 App 生成下一次连接配置后进入磁贴快照，避免新旧名单混用。

## 设备运行失败恢复

三端在核心成功启动后持久化该次规则清单作为可恢复版本；已有连接直接返回成功不会确认尚未使用的新版本。确认版本的文件校验通过后才允许下载下一份更新。恢复记录只保存规则清单及拒绝版本上界，不保存节点或完整连接配置。

新版出现明确的规则加载失败时，先等待平台停止并释放资源，再校验和启用上一成功版本，更新配置中的 provider 路径，最多重新启动一次。Android 同时恢复应用名单及国内应用注释元数据；节点凭据、DNS 和手动规则保持不变。回退不依赖失败版本的应用名单文件。权限、端口、TUN、API 认证和普通连接失败不触发规则回退；用户取消后不继续重试。

失败版本及更旧版本不再自动下载；发布修正必须使用更高快照版本。拒绝记录先于恢复提交，进程中断后下次准备连接会再次恢复已确认快照。旧快照损坏时不强行使用，后续初始化采用保守内置规则。恢复失败不无限重连，保留记录供下次连接处理。该机制降低规则更新影响连接的风险，不能保证所有网络和设备零故障。

恢复记录出现 JSON 截断或字段类型损坏时，不采信其中的确认版本和拒绝版本，按未确认状态处理；真实启动成功后原子重建记录，失败启动不覆盖原文件。未确认前仍禁止下载新版本，文件系统读写错误继续走既有失败恢复路径。已经损坏而丢失的拒绝历史无法凭空还原。
