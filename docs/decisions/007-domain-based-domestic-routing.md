# ADR-007：默认路由使用国内域名直连与国外兜底代理

## 状态

已接受

## 日期

2026-07-25

## 背景

三端此前同时写入国内域名规则集、国内 IP 规则集和本地 GeoIP 规则。实际 Android 流量中，
抖音视频数据大多直连，但 `aweme.snssdk.com`、`mon.snssdk.com`、`is.snssdk.com` 等控制域名
可能未被规则集命中而经境外节点转发，增加延迟并影响刷视频和评论区体验。

GeoIP 路由还让三端配置随本地数据库是否可用而变化：Android 和 Windows 在生成配置时探测
MMDB，macOS 则固定启用。相同用户设置因此可能得到不同的路由语义，也不利于离线审查默认规则。

## 决策

1. 三端默认使用 Mihomo `rule` 模式，按以下顺序生成规则：
   - 用户明确配置的强制代理；
   - 平台内部必须代理的检测域名；
   - OpenAI 等明确的国外代理域名；
   - 固定提交版本的国内域名规则集；
   - `.cn`、抖音/字节常用域名和局域网地址直连；
   - `MATCH,PROXY` 承接所有未命中流量。
2. 运行配置不再写入 `GEOIP` 规则、国内 GeoIP 规则提供器，也不再通过 Mihomo API 刷新该
   提供器。三端不再根据 MMDB 是否存在改变代理路由。
3. 国内域名规则集继续固定到已审查的上游提交，并通过当前代理下载。规则集缺失时，本地
   `.cn`、常用国内域名和局域网规则仍提供有限的离线直连能力。
4. `geoip.metadb` 继续作为 IP 归属显示和可复现发布资产存在；ADR-005 的内容寻址镜像、安全
   校验和更新流程保持有效，但该资产不再决定代理路由。
5. HTTP/HTTPS 订阅获取与兼容策略不在本决策范围内，保持不变。

## 结果

- Android、macOS 和 Windows 对同一订阅生成相同的默认路由语义。
- 抖音/字节常用控制域名无需绕行境外节点；其余已知国内域名由固定国内域名规则集直连。
- 国外及未知流量默认进入用户选中的 `PROXY` 节点，不因 GeoIP 数据缺失或版本变化改变。
- 仅使用 IP、且不在局域网固定网段内的国内目标可能落入 `MATCH,PROXY`。这是取消 GeoIP
  路由后的明确取舍；若未来需要更高的纯 IP 国内直连覆盖，应以独立、可审查的新决策引入，
  不得静默恢复 GeoIP 模式。

## 未采用的方案

### 继续同时使用国内域名与国内 IP 规则集

覆盖面更大，但保留了用户要求取消的 GeoIP 路由模式，并继续让网络行为依赖 IP 数据集。

### 只保留 `.cn` 直连

配置最简单，但会让大量使用 `.com`、`.net` 的国内服务经境外节点转发，无法解决抖音控制
域名的实际问题。

### 复制完整国内域名清单到源码

可以完全离线，但会显著扩大仓库和每次更新的审查面。固定提交的 MRS 规则集加少量高频本地
补充更符合现有发布与资产校验流程。

## 验证守卫

- 共享配置测试要求只生成 `ssrvpn-geosite-cn` 域名提供器，不得出现
  `ssrvpn-geoip-cn` 或任何 `GEOIP` 规则。
- 测试固定校验 `snssdk.com`、局域网 CIDR 和最终 `MATCH,PROXY` 的顺序与存在性。
- 规则提供器刷新测试只允许请求国内域名提供器。

## 后续问题记录 (2026-07-25)

### 问题 1: 运行中 mihomo 核心崩溃但 app 未感知
- **现象**: mihomo 进程已退出，但 TUN 接口 (tun0 198.18.0.1) 和 API 端口 (9090/7890/7891) 仍残留
- **影响**: 所有流量被 TUN 劫持后无核心处理，全部断网
- **根因**: v3.5.1 的 CorePortReleaseVerifier 仅在主动 stop 时生效，核心被动崩溃无检测
- **需要**: 核心存活心跳检测 — 定时检查 mihomo 进程或 API，发现死亡后自动触发清理

### 问题 2: 国内 .com 域名走代理
- **现象**: 瑞幸咖啡工作站 (com.lucky.luckyemployee) 无法联网，因 luckincoffee.com 走了代理
- **根因**: luckincoffee.com 不在 geosite-cn 规则集中，也不在 defaultDirectRules 静态列表
- **路由链**: geosite-cn miss → GEOIP 无法匹配 (fake-ip) → MATCH,PROXY 兜底
- **需要**: 补充常见国内生活服务域名到 defaultDirectRules，或增加 DOMAIN-SUFFIX,.com,DIRECT 的白名单机制
