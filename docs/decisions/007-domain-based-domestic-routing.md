# ADR-007：默认路由使用国内直连与国外兜底代理

## 状态

已接受（2026-07-25 修订）

## 日期

2026-07-25

## 背景

SSRVPN 的目标是让可识别的国内流量直连，其余流量走用户选中的代理，同时允许用户填写少量
必须强制代理的网站。单独依赖域名规则会漏掉直接访问国内 IP 的流量；单独依赖 GeoIP 又无法
在 fake-ip 和加密域名场景下稳定识别目标。DNS 解析路径如果与路由方向不一致，还会造成
`.cn` 强制代理网站仍使用国内 DNS、国内 `.com` 网站使用境外 DNS 等冲突。

[Clash Verge Rev v2.5.2 的配置增强实现][clash-verge-seq]保留 Mihomo 规则的顺序语义：
前置规则、原配置、后置规则按顺序合并，并在使用前[交给核心校验][clash-verge-validate]。
SSRVPN 不复制其 UI 或配置系统，只采用同一原则：显式维护优先级，并对最终生成配置做回归
与核心校验。

## 决策

1. 三端默认使用 Mihomo `rule` 模式，按以下顺序生成规则：
   - 用户填写的强制代理域名或 IP；
   - 平台内部必须代理的检测域名；
   - OpenAI 等明确的国外代理域名；
   - 固定提交版本的国内域名规则集；
   - `.cn`、常用国内域名和局域网地址；
   - 本地 `geoip.metadb` 支持的 `GEOIP,CN,DIRECT`；
   - `MATCH,PROXY` 承接所有未命中流量。
2. 用户强制代理域名同时写入 `nameserver-policy`，使用经 `PROXY` 访问的可信 DoH，并排在
   国内域名集与 `.cn` DNS 策略之前。强制代理 IP 只生成 IP 规则，不生成无效的 DNS 策略。
3. 国内域名规则集和 `.cn` 使用国内 DoH；OpenAI 与用户强制代理域名使用代理 DoH。DNS
   策略顺序必须与路由优先级一致。
4. 国内域名规则集固定到已审查的上游提交并通过当前代理下载。内置 `.cn`、常用国内域名、
   局域网与本地 GeoIP 规则在规则集临时不可用时保留基础直连能力。
5. 三端启用有界的 HTTP、TLS、QUIC 域名嗅探，允许 Mihomo 在 fake-ip 或纯 IP 流量中恢复
   可用于规则匹配的域名。默认不全局改写目标地址，仅对 HTTP 显式启用改写。
6. `geoip.metadb` 是可复现发布资产，也是国内纯 IP 直连的本地兜底。三端必须安装同一份
   已校验数据库；运行时解压失败时允许连接继续，但必须提示国内纯 IP 流量可能回退到代理。
7. HTTP/HTTPS 订阅获取与兼容策略不在本决策范围内，保持不变。

## 结果

- 用户填写的强制代理网站不会被国内域名、`.cn` 或 GeoIP 直连规则覆盖。
- 国内 `.com`、`.net` 等非 `.cn` 域名可通过固定国内域名集和嗅探直连，国内纯 IP 可通过
  本地 GeoIP 数据库直连。
- 国外及未知流量最终进入 `PROXY`，不会因为新增直连规则而意外放行。
- 规则数据集和域名嗅探无法数学意义上识别所有网络流量；未命中的目标按安全兜底走代理。

## 未采用的方案

### 只使用国内域名规则集

无法覆盖没有域名信息的国内纯 IP 流量，偏离“国内流量全部直连”的目标。

### 只使用 GeoIP

fake-ip、CDN、域名级强制代理以及共享地址场景需要域名优先级，单靠 IP 归属无法表达。

### 对所有 `.com` 或 `.net` 直连

会把大量国外网站错误直连，破坏“国外流量全部代理”的兜底目标。

### 复制完整国内域名与 IP 清单到源码

会扩大仓库和更新审查面。固定提交的规则集、内容寻址的本地 GeoIP 资产与少量静态规则更
符合现有发布校验流程。

## 验证守卫

- 共享配置测试固定检查强制代理路由位于所有国内直连规则之前，并检查相同域名的代理 DNS
  策略位于国内域名集与 `.cn` DNS 策略之前。
- 测试要求国内域名集、`GEOIP,CN,DIRECT`、局域网与最终 `MATCH,PROXY` 均存在且顺序正确。
- 测试要求 HTTP、TLS、QUIC 嗅探配置可由 YAML 解析，并固定目的地址改写边界。
- 资产校验固定检查三端使用同一份、哈希匹配的 `geoip.metadb`。
- 发布前使用三端测试及可用平台的真实 Mihomo 核心校验最终配置。
