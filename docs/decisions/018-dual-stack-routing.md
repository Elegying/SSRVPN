# ADR-018：双栈分流与代理目标 IPv4 优先

状态：2026-09-17 本地候选实现，待三端实机验收；取代 ADR-016 的 IPv4-only 边界。

## 行为

智能模式下，IPv4 和 IPv6 使用同一套应用、用户、域名、企业网络、GeoIP 与兜底规则。
国内目标直连，需代理及未知目标经选中节点。全局模式继续遵守已有全局语义，
用户手动规则及 Android 应用优先级不变。IPv6 不再在所有用户规则之前一律拒绝。

核心和 DNS 开启 IPv6，三端 TUN 显式接管 IPv6。接管地址不依赖客户端当前是否有
公网 IPv6，因为节点可通过 IPv4 隧道提供 IPv6 出口。不修改操作系统 IPv6 开关。

共享核心扩展在选定代理出口后，利用原有解析器、缓存和 DNS 分流解析目标域名。
优先尝试最多四个去重 IPv4 地址，再尝试最多四个 IPv6 地址，最后保留原节点远端解析。
地址尝试复用原有有限重试及连接总超时，不增加重试轮数。解析占用该连接预算，最多两秒；
如果一次拨号耗尽总预算，不保证所有候选地址都被尝试，避免通过延长总等待拖住用户。
解析失败不改为直连。内部 DNS 请求跳过此处理，避免循环；直连和拒绝出口不修改目标。
已指定 hosts 和没有可恢复域名的 IPv6 字面地址保留原有语义。
已解析的 IPv4 优先固定到该地址；IPv6 可通过已有 DNS 映射或嗅探恢复的域名选择 IPv4，
原始 IPv6 地址仍保留为回退目标。

这不是 NAT64。IPv6-only 目标通过原节点尝试 IPv6，不假装能转换为 IPv4，
不依据节点服务器地址判断节点的 IPv6 出口能力，不自动换节点或断开整体 VPN。
HTTPS 的 TLS/SNI/HTTP Host 字节不改，变更仅作用于代理协议承载的目标地址。

## 诊断和边界

最终拨号失败且确实尝试过 IPv6 目标时，核心输出固定事件，不含目标或凭据。
认证的 `/ssrvpn/traffic` 增加会话内失败计数和距最近失败的毫秒数；
手动诊断只展示最近一分钟内的失败观察，三端复用同一中文说明。
旧会话迟到结果不写入新会话。失败表示网络、节点或目标的该次访问未成功，
不能证明节点永久不支持 IPv6。旧核心缺字段时不误报。

部分代理协议的 TCP/UDP 不返回远端连接确认，拨号成功不能保证应用层可用。
Hysteria2 等协议可能在首次读取时才返回远端目标连接结果，届时拨号重试已经结束。
现有 IPv6 失败计数仅覆盖最终拨号失败，不是完整的应用层失败统计；计数为零不能证明
IPv6 访问正常。不得为地址回退重放已经发送的应用请求，也不得将代理失败降级为直连。
UDP 无响应尤其不能单独证明 IPv6 能力；不作确定性归因。
本地没有 IPv6 出口的环境无法直连 IPv6-only 国内目标，双栈目标依赖正常 IPv4 回退。
此候选不能代替 Windows TUN、防火墙、真实节点和移动网络的实机验证。
