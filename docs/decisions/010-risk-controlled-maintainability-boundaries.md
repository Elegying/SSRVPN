# ADR-010：以行为证据控制高风险职责拆分

## 状态

已接受

## 日期

2026-08-01

## 背景

SSRVPN 的共享更新、macOS 原生应用委托、Windows 系统代理、Android VPN Service
和 Windows 安装事务同时承担较多职责。其中一部分只是数据模型、下载、发布或窗口/单实例
支持，适合独立验证；另一部分控制代理恢复、核心进程、TUN 文件描述符和跨重启回滚，执行顺序
本身就是安全边界。

按文件行数一次性重写这些热点会放大风险：即使最终测试转绿，也可能改变异步取消、所有权提交、
系统代理恢复或安装回滚的时序。项目需要一个可重复的拆分规则，而不是把“大文件”直接等同于
“必须立即拆完”。

## 决策

1. 只提取具有单一职责、现有行为测试和可机械核对来源的切片；每个切片单独提交并先运行最窄
   专项测试，再进入完整门禁。
2. Dart 私有模型优先使用同一 library 的 `part`，避免为了跨文件访问扩大公开 API。平台原生支持
   类型保持模块内部，不对 Flutter 或第三方建立新接口。
3. 共享更新服务保留 `SharedUpdateService` 公共入口；下载/取消与发布/恢复分别由独立 part
   承担，调用方、错误语义、原子发布和恢复顺序不变。
4. macOS `AppDelegate` 继续负责应用和核心事务编排；核心进程值对象/有界输出、窗口恢复和
   单实例租约由独立 Swift 支持文件承担。单实例文件的 `O_NOFOLLOW`、所有者、普通文件、
   单硬链接与非阻塞 `flock` 检查不得弱化。
5. Windows `SystemProxyService` 继续独占锁、PowerShell 调用、恢复判定和写入顺序；快照、
   恢复动作与取消状态迁入同一 Dart library 的模型 part。
6. Android VPN Service 与 Windows 安装事务在本轮不做跨对象重排。前者已有通知、代际、
   TUN FD、会话和恢复策略边界；后者承担 PowerShell 5.1 下的跨重启文件、注册表、快捷方式
   原子回滚。没有新增目标平台故障注入证据前，只增加规模护栏，不为降低行数继续拆分。
7. 结构门禁固定各入口与支持文件的合理上限，并阻止已迁出的类型回流。上限是触发设计审查的
   阈值，不是质量评分，也不能替代行为测试。

## 不变量

- HTTP 订阅兼容、Android 内置国内应用直连策略、三端 IPv4-only、两页产品表面和既有节点编辑
  手势不变。
- macOS 免费 ad-hoc/未公证与 Windows 未签名安装器单一分发策略不变。
- 核心启动、取消、停止、代理恢复和安装回滚的原有调用顺序、失败关闭与所有权判断不变。
- 重构不得新增外部依赖、网络请求、持久化格式或公开接口。

## 验证

- 共享更新：严格分析、更新服务专项测试和 shared 全量测试。
- macOS：Xcode RunnerTests 真实编译运行，结构门禁检查 Xcode 工程引用和职责回流。
- Windows 系统代理：严格分析以及代理所有权、取消、事务中断和恢复专项测试；Windows CI
  继续验证 PowerShell 5.1、C++ 注册表沙箱与安装/升级烟雾。
- 合并前执行 `make verify`；合并后以受保护 `main` 的完整 CI 为最终自动化证据。

## 后果

- 高频维护入口更短，下载、发布、原生支持与代理模型能够分开阅读和审查。
- 高风险事务没有因追求行数而引入新装载顺序、回调或公共接口。
- Android VPN Service、macOS 核心/代理编排和 Windows 安装恢复仍是需要目标平台证据才能
  继续处理的热点；本决策不会把残余复杂度包装成“已经解决”。
