# ADR-018：规则发布必须经过可靠性审查

日期：2026-09-14。承接 ADR-017，Android 应用名单优先级不变。

## 决策

把原有人工审查和一次性验证转为每次发布的强制门槛。任何审查失败均不签名、不推送候选快照；已公开版本与客户端旧规则保持可用。签名是来源证明，不是规则语义正确的证明，因此必须先检查语义及实际内核加载，再签名。

## 自动门槛

1. 发布器回归与故障注入：覆盖写盘中断、组件版本、名单冲突、核心拒绝和旧发布保留。
2. 受限输入解析：精确包名、浏览器排除、名单互斥、规则行为及大小/数量/语法、危险兜底规则检查。
3. 固定分流期望：`rule-channel/review-cases.json` 包含 14 个国内直连、明确代理和未知公网样本。代理与直连样本不能跨名单冲突；未知样本必须保持未分类，最终由客户端代理兜底。
4. 与上次签名快照比较：先核对旧文件摘要；自动上游文件数量变化不得超出 ±20%，新增或删除任一方向不得超过 `max(20 条, 旧条目数的 10%)`。这可以拦截总数相同的大量替换。人工应用名单允许清空，不受自动上游变动比例约束。
5. 固定内核兼容性检查：官方 Mihomo v1.19.29 Linux amd64，压缩资产 SHA-256 为 `60de76a35a6cbf7b4fa4a20f5c257c24345d1d635ab1aa3877022a1997ef413c`。下载或哈希失败立即阻断；配置语法检查后实际启动隔离内核，要求全部八份公共规则集条目数与候选清单完全一致。检查禁用 TUN、DNS和真实出站流量，不依赖公网网站实时可达。
6. 全部通过后才签名、写入不可变快照、最后提交版本索引。工作流推送失败不强推。来源提交、各文件增删数量、结果或错误写入 Actions 运行摘要。

发布命令、本地内置更新脚本 `scripts/update-smart-rules.py` 和 Python 内部 `build` 函数均必须提供内核，不可跳过核心检查。事务单元测试通过替换审查函数隔离外部进程，不为生产调用保留绕过入口。真实内核配置同时包含两份应用名单的 `PROCESS-NAME` 规则；这验证包名规则可加载，不替代 Android 应用识别和系统排除实测。

## 客户端门槛

继续执行签名、快照摘要、文件摘要、大小/条目数/语法和组件版本校验；完整持久化之后才作为下一次连接的待用版本，下载失败不会清空旧规则。核心规则集未加载完成不得显示连接成功。

源码项目 `scripts/verify-all.sh` 增加发布审查测试，macOS 增加真实定制内核的生产配置流量验证；GitHub macOS CI 同样强制执行 `scripts/check-routing-core.py`。它验证智能、全局、离线回退下的手动例外、GFW 与未知代理行为，补充官方兼容性内核与 SSRVPN 定制版本之间的差异。

## 维护流程与边界

- 发现误分流：先增加预期样本和回归测试，再修复源数据并发布更高版本。不得删除失败样本、篡改期望、放宽门槛或拆分危险变更来绕过审查。
- 大变更被阻断：检查上游固定提交与逐文件差异，确认原因，再通过代码审查调整来源或规则；不自动接受异常候选。
- 每次正式客户端内核升级，同步检查兼容性内核固定版本和摘要，复跑生产配置测试。
- 发布内核下载源独立公开，不依赖 SSRVPN 主项目公开状态。规则仓库依然必须公开可下载。
- 有权限改发布程序、工作流、公钥和样本的人仍能改变门槛；本方案不声称抵御仓库管理员或签名凭据完全失陷。
- 样本不能证明所有网站永远正确，内核加载检查不证明运营商可达性，也不能替代 Android 应用识别/系统排除、Windows 原生恢复及三端实机验收。自动审查可降低故障风险，不能保证零错误。
- 原生磁贴冷启动沿用上次受保护连接配置，App 生成下次配置后才采用新快照。后续客户端已增加明确规则加载失败时的一次自动回退，条件与恢复边界见 ADR-017；历史快照回收仍未新增。
