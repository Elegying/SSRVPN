# 控制 API 端口与会话审查（5.0.6 候选）

## 证据边界

用户提供 5.0.4 日志：9090 健康检查失败三次后串行恢复，随后停核、端口避让至 9091。
用户确认未切换 Wi-Fi、电脑长时间闲置。日志按时间倒序展示；不能把重启时的端口避让
直接认定为此前已运行于 9091，也不能证明 9090 的占用者是遗留核心。

已确认并用回归覆盖的缺陷：

- macOS 运行守护将网络状态查询失败/无物理接口视作确定切换，三次后停止核心。
- 共享健康恢复任务排队期间被新连接替代，旧任务仍可能执行停核。
- 运行设置直接引用可变输入；外部修改输入可能改变后续 API 地址或认证信息。
- 旧代理组查询返回后可能继续查询替代会话；错误消息也可能采用查询结束时的新端口。

前三类是代码与可控测试证据，不是用户具体现场的完整复现。

## 端口及启动路径

保存偏好由平台 SettingsService 持有；`prepareForStart(preferred)` 选择实际端口，
`desiredApiPort` 仅保留预期值用于诊断，运行端口仍只有 `ClashServiceBase` 的运行设置
这一来源。返回的运行设置生成 `external-controller`，全部共享 API 经 `_apiUrl` 使用
`runtimeApiPort`。更新用户偏好不会通过同一对象悄悄改写运行身份。

初始化和重连沿用已有自有进程清理。核心连接顺序：串行连接事务 → 选择端口 → 生成并原子写配置 →
启动核心/授权守护 → 有限、可取消的就绪探测 → 配置/监听和平台状态检查 → 标记运行 →
启用周期监控。macOS TUN 的既有 45 秒窗口、250 ms 探测节奏保持不变；成功立即前进。
Windows 同样在就绪之后启用周期监控。显式端口绑定冲突最多重新选端口尝试一次。

9090 只保留为默认偏好/Android 缺省参数；桌面控制 API 不硬编码该端口。Android 原生
启动与接管使用会话实际端口。桌面普通节点测速采用 TCP 探测，不经 Mihomo 控制 API。

端口选择检查 TCP/必要 UDP、IPv4/IPv6，依次检查相邻端口并有限尝试临时端口。
不通过端口号推断进程归属，更不会杀死未知监听者。自有残留进程沿用平台 PID/启动身份/
路径验证和守护锁；清理无法确认时保留恢复记录或阻止新启动。检测与实际 bind 之间仍有
操作系统级竞争窗口，由显式 bind 冲突的有界重新启动处理。

## 恢复与旧任务保护

周期监控只观察成功进入运行状态的会话，绑定监控代次和连接意图。连续失败达到原门槛
才排入串行恢复；队列执行前重新检查所有权，过期任务不 stop、不覆盖新状态。
平台恢复在停止核心前再次运行当前端口健康检查；恢复正常即保留当前核心。
仍异常时按既有平台清理和有限重建策略执行；没有增加固定 sleep 或重试次数。

控制 API 查询固定一次请求的地址与认证信息，超时终止底层请求；迟到回复按运行代次、
连接意图和实际端口丢弃。GLOBAL 的旧结果不再串联新会话的 PROXY 查询。代理切换也绑定
运行代次，旧请求完成后不能清理新核心的连接。流量及外部网络观察沿用各自既有代次保护。

macOS 暂时无法观察物理网络或 DNS 不再触发守护停核；明确的网络/DNS 变更仍按原策略
处理。核心退出、请求所有者消失和用户断开检查不删除。具体 TUN 终态优先于通用 API
不可达或授权进程退出消息。

## 诊断与未验证项

诊断增加预期/实际/健康检查端口、监听状态和连接意图；平台显示可取得的 PID、进程状态、
启动/停止阶段及 TUN 状态。受权限限制拿不到的 macOS TUN 核心 PID 明确标记未获取，
不把授权进程 PID 冒充核心 PID。诊断只读，不触发授权、不切换网络、不终止进程。

测试覆盖空闲端口、一个/多个端口占用、真实监听避让、不影响无关程序、旧恢复队列、
迟到代理组回复、原生自有进程清理、就绪/取消、持续失效与恢复复核。最终本地与 CI 结果
需在合并前补齐；本文件不将未完成的构建或未做的设备实测标记通过。

尚无该用户完整前置守护日志、长时间闲置真机重现、Windows 10 实机四模式验收。本轮
不得据此承诺所有自动断连均已消除，也不改变订阅格式、节点协议或三端路由优先级。
